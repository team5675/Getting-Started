A result might be absent: Optional

Tell a measured zero apart from no measurement at all.

Why this comes now

Camera results can be missing, and the path loader in your simulation starter asks for a start pose that might be absent. The next lessons depend on keeping “no measurement” separate from a real zero.

You will run lessons/OptionalPractice.java from the home-java-starter folder you already have, in a second VS Code window, then return to your robot project.

See it

Optional represents either a present value or an absent result. Here Optional<Double> means an Optional that may contain a Double number; the angle brackets name the kind of value. Absence is not the same thing as a measured zero. Check presence before get; calling get on an empty Optional throws an exception.

public class OptionalPractice {
    static String describe(java.util.Optional<Double> meters) {
        if (meters.isPresent()) {
            return "Observed: " + meters.get();
        }
        return "No observation: keep estimate";
    }
    public static void main(String[] args) {
        System.out.println(describe(java.util.Optional.of(2.0)));
        System.out.println(describe(java.util.Optional.of(0.0)));
        System.out.println(describe(java.util.Optional.empty()));
    }
}

Try it in OptionalPractice.java

  1. Open. Leave the robot project as it is. In VS Code choose File → New Window, then File → Open Folder and pick the home-java-starter folder from Lessons 2–7 (for example C:\dev\home-java-starter). No new download is needed. Folder missing? Lesson 1 shows how to get it. No run.cmd in it? Add the launcher to an older folder.
  2. Run it unchanged. Press Ctrl+P and open lessons/OptionalPractice.java. Choose Terminal → New Terminal in this window, then type:
    .\run OptionalPractice

    Expected output before you change anything

    Observed: 2.0
Observed: 0.0
No observation: keep estimate
  3. Change, save, run again. Do the task below, save with Ctrl+S and run the same command.
  4. Return. When you have explained the result, close this window. Your robot project is still open in the other sim-starter window. Then press Next.

Run all three cases and explain why zero and missing data must stay distinct. Do not invent a zero pose when a camera provides no valid observation. The training path loader uses getStartingHolonomicPose().orElseThrow(): our supplied path must have a start, and a missing one is a setup error to report.
