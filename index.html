Your first hours with robot programming

A step-by-step guide for someone who has never written code. Start small, see a result, and build from there.

Your first few hours

You do not need to know Java, understand last year’s robot, or have an experienced student beside you. Start with one file and one message. We’ll explain the pieces as you use them.

You need: a Windows laptop with the team’s WPILib 2026 tools, time to try small changes, and somewhere to write a few notes. A mentor can help with installation. No robot, gamepad, GitHub account, or purchased course is needed for Lessons 1–7.

Begin with Lesson 1: the tools →

Already installed? Start with Lesson 2. Returning? Choose your place from the lesson list.

What you’ll do first

Lesson 1 · 30–60 minutes, plus downloads

Get comfortable with the tools

Find the editor, your project folder, and the output area.

Lesson 2 · 35–60 minutes

Run your first program

Run a message, change it, and repair one small mistake.

Lesson 3 · 30–45 minutes

Give information a name

Store a number, change it, and print the result.

Lesson 4 · 30–45 minutes

Make a decision

Ask a true-or-false question and test both possible results.

Plan several short sessions rather than finishing everything at once. After installation, Lessons 2–4 can fill an initial two or three hours, with time to experiment. You can stop earlier. Methods, loops, objects, and commands come in later sessions.

How to use a lesson

  1. Read a small piece. New words are explained where they first appear.
  2. Predict. Say or write what you think the example will do. A guess gives you something to compare.
  3. Try it. Follow the numbered steps and look for the expected output.
  4. Change one thing. Run again and explain the difference.

Copying the first example is fine. Understanding grows when you can change part of it and explain what happened. If a result surprises you, check the last small change. You do not have to fix everything alone.

You can work alone or with a partner

If you work in pairs, swap the keyboard every 10–15 minutes. The person not typing reads the next step and predicts the result. Both people should get time to make a change. If you work alone, say your prediction out loud or write it down.

After about five focused minutes without progress, use the help page or ask a mentor. Show what you expected, what happened, and the first relevant error. Asking is part of the work.

Last year’s code will make more sense later

The guided team examples start with a plain-language idea, explain unfamiliar symbols, and walk through one result. Each reading says which lessons to finish first. You are not expected to understand the full competition program now.
