Return after a break: choose your project

Open WPILib VS Code 2026 and read learning-notes.txt. Choose the folder below for your current lesson. Run your last working example before adding a new change.

Lessons 1–7 · plain Java

  1. Open home-java-starter, containing the lessons folder.
  2. Open the file named by the lesson, make one edit and save with Ctrl+S.
  3. In its PowerShell Terminal, use the Java path from home setup. For example:
& $javaForLessons .\lessons\HelloWorld.java

If you reopened the Terminal, set $javaForLessons again using home setup. Read the new output. These short programs finish by themselves; there is no robot simulator.

Lesson 8 and robot labs · simulation

  1. Open sim-starter, containing build.gradle.
  2. Edit the named Java file and save all changed files.
  3. Disable in the browser station, then stop the previous run with Ctrl+C in its Terminal.
  4. Start the new program:
.\gradlew.bat simulateJava

Wait for “WiredCats training ready,” then open the local station. Choose the mode the lesson names. A compile failure means the new program is not running; fix its first relevant error.

Build prepares the program; simulate runs it on the laptop. This course project has no hardware deployment target. The supplied station controls simulated Driver Station data; do not open a second control GUI.

Save a working version before an experiment

A saved file contains your latest edit. A backup is a separate copy you can return to. A Git checkpoint records selected changes in history; the mentor-guided Git lesson teaches that later. Use this backup route until then:

  1. Save all files. For simulation, click Disabled and stop Java with Ctrl+C first. Stop any build before copying.
  2. In File Explorer, go to the parent folder containing your project. Copy the whole project folder and paste it beside the original, not inside it. For example, keep working in C:\dev\sim-starter and name the copy sim-starter-before-lab-1.
  3. Open the copy in File Explorer and confirm it contains the expected source files. Record its name and your last working result in learning-notes.txt. Continue editing the original project in VS Code.
  4. To recover, preserve your current experiment too. Use File → Open Folder to open the saved copy, verify its name, and run its last known working example. Do not erase your experiment to recover a version.

This is a local backup, not Git history or an off-computer backup. A freshly extracted ZIP is not automatically a Git repository. No GitHub account is needed for this route.

Choose the problem that matches what you see

The WPILib commands are missing

Open the WPILib VS Code 2026 shortcut. Use Ctrl+Shift+P, not Ctrl+P. If the tools still do not appear, ask a mentor to check installation.

The first build is taking a long time

A first build may prepare tools or download dependencies. Look for ongoing messages rather than starting a second build. If it reports a download/network failure, ask for setup help; changing Java syntax will not fix that.

There are many red underlines

Wait for the project to load. Run a build and read the first relevant Java error, including its filename and line. One missing brace or quote can produce many later errors; fix the first cause and build again.

The error says “cannot find symbol”

Check spelling and capitalization first. Was that variable or method declared? Is it in the correct block or class? Read the line above too. Later, a missing import can cause this message.

The error says “package ... does not exist”

Check that you opened the correct project folder and are using the 2026 tools. A library may be absent or mismatched. Ask a mentor before installing libraries. The early lessons need no vendor libraries.

The error says a variable or method is already defined

You may have pasted a new example alongside the old one. When a calculation lesson says replace practice(), replace only that helper instead of adding another. Do not delete unrelated template methods.

The program still prints the old message

Save the right file, stop the old run, and run the file again (or restart simulation for robot lessons). Make sure you are reading that run’s Terminal, not earlier output. A failed build cannot run the new version.

The simulator opens but no robot moves

Lessons 2–7 are plain Java: run their files in the Terminal, without simulation. Lesson 8 uses the separate sim-starter and its browser station. Later simulation labs add movement after you connect the default command.

I accidentally deleted something

Try Ctrl+Z in the editor to undo the recent edit. Compare with the lesson’s small code block. If unsure, stop and ask before deleting more or replacing the entire file.

I do not know what to ask

Say: “I am on lesson __, step __. I expected __. Instead I saw __. The last thing I changed was __.” Show the relevant code and the first useful error or output. You do not need to know the cause before asking.

A word guide to use as needed

You do not need to memorize this list before starting. Come back when a word blocks your understanding.

Source code
The human-readable instructions in files such as Robot.java.
Project
A folder containing code and the files that tell tools how to build it.
Template
A prepared starting project that already contains framework code.
Java
The programming language used in these lessons.
WPILib
The FRC programming libraries and tools used by the project.
Editor
The place where you read and change source text.
Terminal / console output
The panel where build messages and printed program output appear.
Statement
One instruction, often ending with a semicolon.
Syntax
The spelling, punctuation, and structure Java expects.
Type
The kind of value a variable can hold, such as int, double, boolean, or String.
Variable
A named place to hold a value or a reference to an object.
Assignment
Storing a value using =. It replaces the previous value in that variable.
Condition
An expression that produces true or false.
Method
A named block of code you can call.
Parameter / argument
A parameter names an input in a method definition; an argument is the value passed in a call.
Return
Hand a result back to the caller and end that method call.
void
A method return type meaning no result value is returned.
Class / object
A class defines a kind of thing; an object is one instance created from it.
Field / local variable
A field belongs to an object (for the examples here); a local variable belongs to a method or block’s work.
Constructor
Setup code called when an object is created with new.
Import / package
A package groups classes; an import makes another class’s short name available in a file.
Subsystem
A class grouping state and operations for one part of a robot or simulation.
Command
An action the framework can start, run, and end.
Scheduler
The framework code that manages command lifecycles and calls subsystem periodic methods.
Requirement
A declaration that a command needs exclusive use of a subsystem while it runs.
Timeout
A limit that ends an action after a duration.
Git / GitHub
Git records code history; GitHub hosts repositories so people can share and review it. They come later in this learning path.
