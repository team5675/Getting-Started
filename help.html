Help when you need it

Find a next step, read an error message, decode a symbol, or look up a word. You do not have to understand everything at once.

Return after a break: choose your project

Open WPILib VS Code 2026 and read learning-notes.txt. Choose the folder below for your current lesson. Run your last working example before adding a new change.

Lessons 1–7 · plain Java

  1. Open home-java-starter, containing the lessons folder.
  2. Open the file named by the lesson, make one edit and save with Ctrl+S.
  3. In its Terminal, type .\run and the lesson file’s name (Lesson 1, step 3). For example:
.\run HelloWorld

Read the new output. These short programs finish by themselves; there is no robot simulator. No run.cmd in your folder? Add the launcher to an older folder.

Lesson 8 and robot labs · simulation

  1. Open sim-starter, containing build.gradle.
  2. Edit the named Java file and save all changed files.
  3. Disable in the browser station, then stop the previous run: click in its Terminal and press Ctrl+C. If Windows asks “Terminate batch job (Y/N)?”, type Y and press Enter.
  4. Start the new program:
.\robot

Wait for “WiredCats training ready,” then open the local station. Choose the mode the lesson names. A compile failure means the new program is not running; fix its first relevant error. No robot.cmd in your folder? Add the launcher to an older folder.

Already started with an earlier download?

Use these steps if your folder has no run.cmd (Java foundations) or robot.cmd (simulation starter), or if your robot.cmd answers Task 'lab8' not found or Task 'lab7' not found. Both mean your folder came from an earlier download. Add or replace just that one file. Keep everything else you made.

  1. Save all files. For simulation, click Disabled and stop Java first. Make a backup copy of your project folder.
  2. Download the latest Java foundations or simulation starter ZIP. Extract it to a separate temporary folder, such as C:\dev\new-download. Never extract it over the project you have been editing.
  3. From the temporary folder, copy only run.cmd into your existing home-java-starter folder (beside lessons), or only robot.cmd into your existing sim-starter folder (beside build.gradle). If Windows says the destination already has a file named robot.cmd, choose Replace the file in the destination. Replace only that one file.
  4. Reopen your own project in VS Code, open a new Terminal and run your last working example, for example .\run Methods check or .\robot. If you came here from Lesson 8 or Lab 7, type .\robot lab8 or .\robot lab7 again. Your Java files, learning notes and saved paths are unchanged.

The new launcher adds the new commands only. Your lesson files, lab files and station page stay as they were in your earlier download, so a comment or button label may differ slightly from this website. That is expected: keep working in your own files.

You can delete the temporary folder afterwards.

Build prepares the program; simulate runs it on the laptop. This course project has no hardware deployment target. The supplied station controls simulated Driver Station data; do not open a second control GUI.

Save a working version before an experiment

A saved file contains your latest edit. A backup is a separate copy you can return to. A Git checkpoint records selected changes in history; the mentor-guided Git lesson teaches that later. Use this backup route until then:

  1. Save all files. For simulation, click Disabled and stop Java with Ctrl+C first. Stop any build before copying.
  2. In File Explorer, go to the parent folder containing your project. Copy the whole project folder and paste it beside the original, not inside it. For example, keep working in C:\dev\sim-starter and name the copy sim-starter-before-lab-1.
  3. Open the copy in File Explorer and confirm it contains the expected source files. Record its name and your last working result in learning-notes.txt. Continue editing the original project in VS Code.
  4. To recover, preserve your current experiment too. Use File → Open Folder to open the saved copy, verify its name, and run its last known working example. Do not erase your experiment to recover a version.

This is a local backup, not Git history or an off-computer backup. A freshly extracted ZIP is not automatically a Git repository. No GitHub account is needed for this route.

When Java prints an error

If your file has a mistake, Java does not run it. It prints a message like this instead:

C:\dev\home-java-starter\lessons\HelloWorld.java:8: error: ';' expected

  1. Before error: are the file and the line number. Here, line 8 of HelloWorld.java.
  2. After error: is what Java noticed. Find it in the list below.
  3. Under the message, Java repeats your line with a ^ under the spot where it noticed the problem. The mistake is there or just before it, sometimes at the end of the line above.
  4. Fix only the first error. Save, and run again. One missing brace can cause 20 or more errors that all disappear together.
  5. The last line, error: compilation failed, only means that nothing ran. Scroll up to the first error.

Each message below is what Java prints, followed by what it usually means in Lessons 2–7.

';' expected
A semicolon is missing at the end of a statement. Fix: Add ; at the end of the line Java shows, or of the line above it.
unclosed string literal
A text value is missing its closing quote. Fix: Put a straight " at both ends of the text.
package system does not exist
system was typed with a small s. Fix: Write System with a capital S. In the robot project, another package name here can mean a missing library: check that you opened the right project folder, and ask a mentor before installing anything.
cannot find symbol
Java does not know a name. The symbol: line under it says which one, such as variable distanceMeter or class string. Fix: Copy the name exactly from where it was declared; capitals matter. println has a lowercase l (“print line”), not a capital I. String starts with a capital. Creating an object needs new. A variable declared inside braces { } exists only inside them.
variable runs is already defined in method main(String[])
The type word was written again on an update line, or an example was pasted twice. Fix: Declare once, int runs = 4;, then update without the type: runs = runs + 1;. Delete a pasted second copy.
incompatible types: possible lossy conversion from double to int
A number with a decimal part is going into an int. Fix: Use double for measurements. Keep int for whole-number counts.
incompatible types: double cannot be converted to boolean
An if condition uses one =, as in if (volts = 11.0). Fix: Compare with <, > or ==. One = stores a value.
'else' without 'if'
A semicolon right after if (...) ended the if early, or a brace is missing before else. Fix: Remove the ; after the condition. Check that each { has its }.
illegal start of expression
A method was written inside main, or a } is missing above. Many more errors often follow. Fix: Move the method out of main’s braces, but keep it inside the class. Fix this first error, then run again.
not a statement
A calculation has nowhere to go, like centimeters / 100.0;. Fix: Put return in front of it, or store it in a variable.
missing return statement
A method that promises a value can reach its end without returning one. Fix: End the method with a return, such as return value;.
method clamp in class Methods cannot be applied to given types;
A call has the wrong number or kind of inputs. The required: and found: lines show the difference. Fix: Give one value for each parameter, in order.
variable value might not have been initialized
int value = value + 1; makes a new variable instead of changing the field. Fix: Remove int: value = value + 1;.
reached end of file while parsing
A closing } is missing at the end of the file. Fix: Add the missing }. Every { needs one.
class, interface, enum, or record expected
An extra } closed the class early, so the code after it is outside the class. Often many errors. Fix: Remove the extra }. It is above the line Java points to.

The program runs, but the answer is wrong

Java runs these mistakes without an error, exactly as written.

  • TRY AGAIN: for four; expected 10; got 4 means the program ran but one answer is wrong. Compare expected with got, then reread the TASK and HINT at the top of the file. This one happens when total = 0; is inside the loop, so total starts over on every pass. Set it once, before the loop.
  • TRY AGAIN: first object; expected 2; got 3: the Counter field is static, so every counter shares one number. Remove static.
  • if (enabled = true) stores true instead of comparing, so that branch always runs. Write if (enabled).
  • if (volts < 11.0); with no else after it: the semicolon ends the if, so the block below always runs. Remove the ;.
  • The program never finishes: a while loop has no update, so its condition stays true. Click in the Terminal and press Ctrl+C. If Windows asks Terminate batch job (Y/N)?, type Y and press Enter. Then add the update, such as i++;, inside the loop.

Messages from .\run and .\robot

The term '.\run' is not recognized (or '.\robot')
The Terminal is in a different folder, or your folder came from an earlier download that has no launcher file. Do this: Check that the prompt ends in home-java-starter> or sim-starter>. If the Explorer panel shows no run.cmd or robot.cmd, add the launcher to an older folder.
There is no lessons\Valuse.java in this folder. Check the spelling.
The name after .\run does not match a lesson file. The lines under the message list the real names. Do this: Type one of the listed names, such as .\run Values.
Could not find the Java that WPILib 2026 installs.
WPILib 2026 is not installed on this computer, or it is in an unusual place. Do this: Do Lesson 1, step 1. On a school or shared computer, ask a mentor.
The Java found at … is not Java 17.
A computer setting points the launcher at a different Java. Do this: Ask a mentor.
error: compilation failed
Java found a mistake in your file, so nothing ran. Do this: Scroll up to the first line containing error: and use the list above.
Task 'lab8' not found (or 'lab7')
Your robot.cmd came from an earlier download, so it passed the word to Gradle. Do this: Get the newer robot.cmd, then try again.
Terminate batch job (Y/N)?
You pressed Ctrl+C to stop a running program. Do this: Type Y, then press Enter.

Choose the problem that matches what you see

The WPILib commands are missing

Open the WPILib VS Code 2026 shortcut. Use Ctrl+Shift+P, not Ctrl+P. If the tools still do not appear, ask a mentor to check installation.

The first build is taking a long time

A first build may prepare tools or download dependencies. Look for ongoing messages rather than starting a second build. If it reports a download/network failure, ask for setup help; changing Java syntax will not fix that.

There are many red underlines

Wait for the project to load. Run it and read the first Java error, including its filename and line (how to read an error). One missing brace or quote can produce many later errors; fix the first cause and build again.

The program still prints the old message

Save the right file, stop the old run, and run the file again (or restart simulation for robot lessons). Make sure you are reading that run’s Terminal, not earlier output. A failed build cannot run the new version.

The simulator opens but no robot moves

Lessons 2–7 are plain Java: run their files in the Terminal, without simulation. Lesson 8 uses the separate sim-starter and its browser station. Later simulation labs add movement after you connect the default command.

I accidentally deleted something

Try Ctrl+Z in the editor to undo the recent edit. Compare with the lesson’s small code block. If unsure, stop and ask before deleting more or replacing the entire file.

I do not know what to ask

Say: “I am on lesson __, step __. I expected __. Instead I saw __. The last thing I changed was __.” Show the relevant code and the first useful error or output. You do not need to know the cause before asking.

A word guide to use as needed

You do not need to memorize this list before starting. Come back when a word blocks your understanding. The small label shows where the word first matters.

Tools and files

Source code
The human-readable instructions in files such as Robot.java.
Project
A folder containing code and the files that tell tools how to build it.
Template
A prepared starting project that already contains framework code.
Java
The programming language used in these lessons.
WPILib
The FRC programming libraries and tools used by the project.
Editor
The place where you read and change source text.
Terminal / console output
The panel where build messages and printed program output appear.
Launcher: .\run, .\robot · Lesson 1
A one-word command saved in your project folder as run.cmd or robot.cmd. It finds the Java that WPILib installed and starts your program.
Compile, compiler error · Lesson 2
Before running your file, Java checks all of it. A compiler error means it found something it cannot read, so nothing runs. Common messages.
Gradle · Robot project
The tool that builds and runs the robot project. .\robot starts it for you.
Log, AdvantageScope · Debugging
A log is a recording of named values over time. AdvantageScope draws graphs from it.
Git / GitHub
Git records code history; GitHub hosts repositories so people can share and review it. They come later in this learning path.

Java words

Statement
One instruction, often ending with a semicolon.
Syntax
The spelling, punctuation, and structure Java expects.
Comment · Lesson 2
A note for people, starting with //. Java skips the rest of that line.
Type
The kind of value a variable can hold, such as int, double, boolean, or String.
int, double, boolean, String · Lesson 3
A whole number; a number that can have a decimal part; true or false; text in quotes.
Variable
A named place to hold a value or a reference to an object.
Declaration · Lesson 3
The line that creates a variable and gives its type, such as int runs = 1;. Declare each name once.
Assignment
Storing a value using =. It replaces the previous value in that variable.
Condition
An expression that produces true or false.
Boundary · Lesson 4
The exact value where an answer changes, like 11.0 in volts < 11.0. Always test it.
Loop, pass · Lesson 6
A loop repeats a block of instructions. One trip through the block is a pass.
++ · Lesson 6
Add one. i++ does the same as i = i + 1.
Accumulator · Lesson 6
A variable that collects a running total. Declare it before the loop.
Method
A named block of code you can call.
Parameter / argument
A parameter names an input in a method definition; an argument is the value passed in a call.
Return
Hand a result back to the caller and end that method call.
void
A method return type meaning no result value is returned.
static, public, private · Lessons 2, 5 and 7
static: belongs to the class itself, so main can call it without creating an object. public: other classes may use it. private: only this class may.
Class / object
A class defines a kind of thing; an object is one instance created from it.
Field / local variable
A field belongs to an object (for the examples here); a local variable belongs to a method or block’s work.
Constructor
Setup code called when an object is created with new.
this · Lesson 8
“This object’s own.” this.light means the object’s light field when a constructor parameter has the same name.
extends, @Override · Robot project
extends: this class starts from another class. @Override: “I am replacing a method I inherited; check my spelling.”
Callback · Robot project
A method you write that the framework calls for you at the right moment.
Import / package
A package groups classes; an import makes another class’s short name available in a file.

Robot words

Disabled, Autonomous, Teleop · Robot project
Robot modes. Disabled: nothing moves. Autonomous: the robot follows its own plan. Teleop: a driver is in control.
Station · Robot project
The browser page with your pretend driver controls and the robot map.
Subsystem
A class grouping state and operations for one part of a robot or simulation.
Command
An action the framework can start, run, and end.
Scheduler
The framework code that manages command lifecycles and calls subsystem periodic methods.
Requirement
A declaration that a command needs exclusive use of a subsystem while it runs.
Trigger · Lab 1
An object that watches a button and starts or stops a command.
Default command · Robot basics 3
The command a subsystem runs whenever no other command is using it.
Timeout
A limit that ends an action after a duration.
Alert · Advanced 7
A named warning the robot shows when something is wrong.
