Check the camera with a tape measure

A camera can report the same wrong answer very confidently. Learn how the team checks it against something it can’t fool.

Today’s small goal

Check a camera’s answer against an independent measurement. Separate a steady mistake (bias) from noise (scatter), and decide pass, fail or “we can’t tell yet”.

1. A confident answer can still be wrong

A camera with a wrong mount or lens calibration doesn’t look broken. It reports a steady, believable pose, and the dashboard shows the robot in a slightly wrong place. Recalibrating doesn’t settle it either: a calibration can match its own pictures well and still be wrong. The only way to know is to compare the camera with something it didn’t produce.

That “something” is the reference: where the robot really is, measured by people with a tape measure, a meter stick and a jig, a simple frame that holds the robot at a measured x, y and heading. The reference must not come from the camera, the dashboard map, or a tag whose position you are testing. How a jig works, and how precisely it places the robot, is part 1 of the optional camera track.

2. Work it out by hand: three readings

The robot sits still in the jig at x = 2.00 m. The camera reports x three times. Subtract the reference from each reading:

ReadingCamera x (m)Reference x (m)Camera − reference (m)
12.032.00+0.03
22.042.00+0.04
32.022.00+0.02
Average2.032.00+0.03

Every reading is too far, by 2 to 4 cm. The average of the differences, +0.03 m, is the steady part of the mistake. The readings themselves spread over only 2 cm, from 2.02 to 2.04. Those two numbers answer two different questions:

  • Bias: the average reading minus the reference. Here +0.03 m. A steady mistake, the kind a wrong mount causes.
  • Scatter: how spread out the readings are around their own average. Noise, from motion, blur, lighting or distance.

A tight cluster with a large bias is the dangerous case: the readings agree with each other, so they look trustworthy, yet they are all wrong in the same direction.

3. Let the code do the arithmetic

With ten readings, arithmetic by hand is slow, so two supplied helper methods do it. average adds the values and divides by how many there are, as in the table. scatter returns the standard deviation: roughly, the typical distance of one reading from the average. You do not need to follow its formula today; part 2 of the optional camera track works it out by hand.

Where this goes: in Robot.java, paste these two helpers once, inside the class and below practice(). They have no @Override.

Supplied helpers

// Supplied helpers: paste both into Robot.java once, below practice().
private double average(double[] values) {
    double sum = 0.0;
    for (double value : values) {
        sum = sum + value;
    }
    return sum / values.length;
}

private double scatter(double[] values) {
    double mean = average(values);
    double sumOfSquares = 0.0;
    for (double value : values) {
        sumOfSquares = sumOfSquares + (value - mean) * (value - mean);
    }
    return Math.sqrt(sumOfSquares / (values.length - 1));
}

The bias matches the table. The scatter is 1 cm: a typical reading sits about 1 cm from the average of 2.03. That is not the 2 cm in the table, and both are right: the table’s 2 cm is the range, the largest reading minus the smallest, while this helper uses the standard deviation.

Ten frames are not ten measurements

Ten pictures from one placement all share the same placement mistake. To learn how repeatable the jig is, remove the robot and place it again, at least three times, and compare. Many frames from one placement only measure the camera’s noise.

4. Pass, fail, or we can’t tell yet

The reference has its own uncertainty: the tape measure, the jig, the offset to the robot’s center. Suppose the jig places the robot to within 0.010 m. Then the camera’s true error is somewhere between the bias size minus 0.010 and the bias size plus 0.010. Compare that whole range with an invented 0.050 m limit:

Bias size (m)Reference uncertainty (m)True error could be (m)Against 0.050Decision
0.0310.0100.021 to 0.041all belowPASS
0.0310.0250.006 to 0.056crosses the limitINCONCLUSIVE
0.0700.0100.060 to 0.080all aboveFAIL

This is a simplified rule that treats the reference uncertainty as a hard bound. A real acceptance decision also has to consider how well the camera’s average is known, repeated placements and a confidence level.

Where this goes: replace only practice() again. This version keeps the bias and scatter lines and adds the decision. Keep the two helpers.

Code to use

private void practice() {
    double referenceX = 2.000; // measured with the jig and a tape measure
    double[] cameraX = {2.031, 2.027, 2.035, 2.029, 2.033, 2.030, 2.028, 2.034, 2.032, 2.031};
    double bias = average(cameraX) - referenceX;
    System.out.println("Bias:    " + String.format("%+.4f", bias) + " m");
    System.out.println("Scatter: " + String.format("%.4f", scatter(cameraX)) + " m");

    double limit = 0.050;                // invented 5 cm limit for this exercise, not a team acceptance limit
    double referenceUncertainty = 0.010; // how well the jig placement is known
    double size = Math.abs(bias);
    if (size + referenceUncertainty <= limit) {
        System.out.println("PASS");
    } else if (size - referenceUncertainty > limit) {
        System.out.println("FAIL");
    } else {
        System.out.println("INCONCLUSIVE: measure the reference better");
    }
}

The camera didn’t change, only how well we know the truth. The team’s rule of thumb is to make the reference uncertainty about a third of the error you want to catch, or smaller.

5. Does the evidence support the claim?

One station that passes says the camera is right at that station. To claim more, measure at least two stations with different positions, headings and distances. If you then change something, such as a mount angle, test the change at a third station that you did not use while choosing it. If that station fails, the change was wrong, however good the first ones looked. Never change the mount, the lens and the field map all at once to make one view look right.
