PAUSE & PREDICT

What does the log actually prove?

Separate what was recorded from what you think happened. An Enabled change is evidence about robot state; it does not prove that a wheel moved.

1. Read a value and its time

A log is a recorded history. A topic names a value, such as /DriverStation/Enabled. A timestamp tells when that value was recorded on the log’s clock. Here, time increases in seconds; it is not the match countdown.

2. Predict, calculate, explain

  1. Find the two intervals where Enabled is true. Subtract each start time from the following false time.
  2. Calculate the disabled gap between those intervals.
  3. Write one sentence containing a value and an interval. Then write a possible explanation in a separate sentence.
  4. Name another signal that would help test your explanation. Does being enabled prove the robot moved?
Check your reasoning after trying

The first enabled interval lasts about 20.76 seconds. The disabled gap is about 3.98 seconds. The second enabled interval lasts about 140.09 seconds. The Enabled signal alone does not identify autonomous versus teleop or prove motor motion. Inspect mode signals and measured speed for those questions.

3. Why only five rows?

AdvantageKit can save a field when it changes and record robot-cycle timestamps separately. Five saved changes do not mean five trips through the robot loop. A flat graph can mean an unchanged value. It can also mean data stopped arriving. Check heartbeat, validity and measurement age before deciding which explanation fits.

After arrays and loops: count false-to-true transitions in {false, true, false, true, false}. Start at index 1 and compare the previous state with the current state. An if decides whether to count. Explain why starting at index 1 makes sense for this comparison but skipped useful data in the earlier sum exercise.

4. Four different meanings of “time”

What are we discussing?What to check
The robot loopWPILib’s default TimedRobot period is 20 ms, or 50 cycles per second. Programs can configure other periods.
The saved recordA WPILOG file stores each record’s time in microseconds.
A timestamp stored as a valueAn individual logged value can use another unit, such as nanoseconds. Read its metadata.
The viewer’s display intervalA 50 ms display grid is 20 displayed samples per second. A 20 ms grid is 50. Changing the grid cannot recover measurements that were never recorded.

These are different from camera frame rate, CAN signal rate and odometry update rate. A faster controller does not make every signal the same speed.

The table was checked against WPILib 2027 alpha 7 (default loop period; WPILOG 1.0 record timestamps in microseconds, unchanged from 2026) and AdvantageKit 27 alpha 6 (its Timestamp value uses nanoseconds). References: file format, default loop, and timestamp metadata.

5. Open the complete story with a mentor

The full match recordings are not downloaded by this page; your mentor has them. At home, use AdvantageScope, included with the stable tools. In a guided session your mentor may open the team’s own viewer instead. Whichever viewer you use, choose the topics yourself and check them against the table in section 1: a tool’s automatic label is not a measurement.

For mentors

The team keeps the original browser-based Unified WPILOG Analyzer v10 and a local v11 with a beginner guided mode; neither file is on this website. v11 brings field playback, battery/current graphs, camera detections and camera-layout exploration together. You have the paired akit_... / FRC_... files for E3, E8, E11, E13, E14 and E15; open one match pair at a time, since unrelated matches are separate runs. v10 is preserved as a historical tool; its automatic clock, topic and match-window choices have known problems. v11 adds checks and guidance, but its labels still need evidence, and camera contribution and inferred-path views remain estimates. Use AdvantageScope with explicitly selected topics as a comparison.

The E3 extract’s manifest identifies the source log by SHA-256; the source robot commit is not established. Parser checks are not hardware validation or a full viewer acceptance test.

For a first graph, select /SystemStats/BatteryVoltage from the E3 AdvantageKit file. Then compare /RealOutputs/Power/BatteryVoltage on the same time axis. These are different logged sources and have different minima and recording cadences. Ask where each came from before choosing one. For current, the useful changing topic is /RealOutputs/Power/TotalCurrent; /PowerDistribution/TotalCurrent in this sample contains only one zero value. Zero does not prove the robot consumed no current.

6. In the 2027 practice code

The current robot records Drive/Pose, Drive/OdometryOnlyPose, Power/SwerveSupplyAmps and per-camera AcceptedCount, AgeSeconds and LastRejectReason. Use the source map to read their definitions. A swerve motor-current sum is not total robot current. Receiver prefixes can differ between a saved log and NetworkTables.

Later lessons return to these same questions: did a command start and end, did the robot follow the path, and was a camera correction fresh and accepted? A pose drawn on the field is an estimate, not an independently measured ground truth.
