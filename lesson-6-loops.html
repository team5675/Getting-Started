The lesson’s for header is split across three lines to highlight initialization, comparison and increment. After printing, execution goes back up to the increment, then checks the condition again. It prints Count: 1, Count: 2, Count: 3, then stops when count becomes 4. It is a Java trace, not a robot motion simulation.

1. Start with repetition you can see

Three separate statements can print three numbers:

Reading example — three separate instructions

System.out.println(1);
System.out.println(2);
System.out.println(3);

A loop repeats a block. We will use a for loop with a small, known range. This is about repetition, not robot movement.

2. Replace the startup method

Where this goes: open src/main/java/frc/robot/Robot.java. Replace only the robotInit() method you added earlier, from its @Override line through that method’s matching closing brace. Keep the rest of the file. Do not add a second robotInit().

Code to use

@Override
public void robotInit() {
    for (int count = 1; count <= 3; count++) {
        System.out.println("Count: " + count);
    }
    System.out.println("Finished counting");
}

There are three parts between the for parentheses, separated by semicolons:

PartWhen it happensMeaning
int count = 1Once, before the first checkCreate a local counter starting at 1.
count <= 3Before each passContinue only while the count is at most 3.
count++After each completed passAdd 1 to count. Here this has the same effect as count = count + 1.

6. A loop must be able to finish

If the counter never changes, a condition can stay true forever. That is an infinite loop. Do not deliberately run one for this exercise. If you accidentally do, stop the simulation from its Terminal and check the update part.

Robot code has another kind of repetition: WPILib calls robotPeriodic() repeatedly, normally about every 20 milliseconds. That is about 50 times per second. Each call needs to return so the framework can do other work. Later, check a sensor once per call rather than putting a waiting loop inside that callback.

A bounded while loop for the workbook

A while loop asks its condition before each pass. It can do the same counting as a for loop, but you must put the starting value and the increment in the right places:

int count = 1;
while (count <= 3) {
    System.out.println(count);
    count++;
}

Expected: 1, 2, 3 on separate lines. When count becomes 4, the condition is false. Without count++, this would never stop. This finite console exercise is different from waiting in robot code for a sensor. A robot periodic method must return promptly.

In the real robot · 2027Practice

Source map and exact reviewed versions · Private team repository; excerpts remain readable here.

A robot can have one camera or several. Instead of copying the same check for each one, the code loops over all of them. This loop asks “is ANY camera connected?”:

Reading example from src/main/java/frc/robot/subsystems/monitor/SystemHealthCheck.java — do not paste

boolean anyCamera = false;
for (int i = 0; i < vision.getCameraCount(); i++) {
  anyCamera |= vision.isCameraConnected(i);
}

Same three parts as your counting loop: start at 0, keep going while i is less than the number of cameras, and add 1 each pass. Counting from 0 is normal in Java, as Part 2 explains. For booleans, anyCamera |= … combines the old value and the new answer with OR: once one camera answers, it stays true. It still evaluates the camera check on every pass. || also means OR, but skips its right-hand expression when the left side is already true.

The robot runs loops like this many times a second, every 20 milliseconds. Adding a second camera needs no new checking code.
