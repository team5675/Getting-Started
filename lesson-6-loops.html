1. See it

A for loop has a starting value, a condition and an update. This one prints 1, 2 and 3:

for (int i = 1; i <= 3; i++) {
    System.out.println(i);
}
PAUSE & PREDICT

Does the counter stop at 3?

Follow the final increment and one more condition check. Compare the last value printed with the value used in that final check.

i++ adds one after each pass. After printing 3, i becomes 4; the condition is false and the loop ends. A while loop checks its condition before each pass too, but you write the update in the body. A missing update can cause an endless loop.

int i = 1;
while (i <= 3) {
    System.out.println(i);
    i++;
}

Later, WPILib calls periodic methods repeatedly. Those methods must return quickly. Do not put an endless loop or a wait-for-hardware loop inside them.

The lesson’s for header is split across three lines to highlight initialization, comparison and increment. After printing, execution goes back up to the increment, then checks the condition again. It prints Count: 1, Count: 2, Count: 3, then stops when count becomes 4. It is a Java trace, not a robot motion simulation.

Keep a running total

The accumulator begins outside the loop so it remembers previous additions. Trace total after each pass: 1, 3, then 6.

int total = 0;
for (int i = 1; i <= 3; i++) {
    total = total + i;
}
System.out.println(total); // 6

Part B · make a change yourself

Count in the other direction

In Loops.java, add a for loop inside main after the existing output lines. Print the numbers 5, 4, 3, 2, 1, each on its own line. Decide the starting value, condition and update yourself. Use count = count - 1 to subtract one. Predict the first value that fails the condition. Then start at 1, and finally 0, to check the boundaries. Restore the start to 5. Do not run an intentionally endless loop.

A hint after you try

The condition must include 1 and exclude 0. Starting at 1 prints one line; starting at 0 prints nothing. Choose a start, a condition and an update before looking at the solution.

Compare a complete solution after trying

Trace the next comparison after 1 prints:

for (int count = 5; count >= 1; count = count - 1) {
    System.out.println(count);
}

3. Check an edge case

Check n = 0: the body runs zero times and the result is 0. Explain why <= includes n and < leaves it out. Ctrl+C stops an accidental endless loop; if Windows then asks “Terminate batch job (Y/N)?”, type Y and press Enter.

If you get stuck

Java’s message starts with the file and the line number. Read the words after error:, fix only the first error, save, and run again.

TRY AGAIN: for four; expected 10; got 4
The line total = 0; is inside the loop, so total starts over on every pass. Set it once, before the loop.
The program never finishes
A while loop has no update, so its condition stays true. Click in the Terminal and press Ctrl+C. If Windows asks Terminate batch job (Y/N)?, type Y and press Enter. Then add i++; inside the while body.
cannot find symbol and symbol: variable i or symbol: variable total
A variable declared inside a loop, or in the for line, exists only inside that loop. Declare total before the loop, and return total, not i.

Robot glimpse · one idea to notice

The robot repeats a connection check for each camera. Notice that a loop lets the same instructions handle several cameras without copying the instructions for each one.

In the real robot · 2027Practice

Source map and exact reviewed versions · Private team repository; excerpts remain readable here.

A robot can have one camera or several. Instead of copying the same check for each one, the code loops over all of them. This loop asks “is ANY camera connected?”:

Reading example from src/main/java/frc/robot/subsystems/monitor/SystemHealthCheck.java — do not paste

boolean anyCamera = false;
for (int i = 0; i < vision.getCameraCount(); i++) {
  anyCamera |= vision.isCameraConnected(i);
}

Same three parts as your counting loop: start at 0, keep going while i is less than the number of cameras, and add 1 each pass. Counting from 0 is normal in Java, as Part 2 explains. For booleans, anyCamera |= … combines the old value and the new answer with OR: once one camera answers, it stays true. It still evaluates the camera check on every pass. || also means OR, but skips its right-hand expression when the left side is already true.

The robot runs loops like this many times a second, every 20 milliseconds. Adding a second camera needs no new checking code.

From the team’s 2027 practice-bot code (repository 2027Practice, branch codex/camera-verification, October 2026). It is built with the 2027 test version of WPILib, so a few names differ from your 2026 tools. Read it; don’t paste it.
