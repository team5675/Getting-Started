Many values: ArrayList and EnumSet

Keep a list that grows, and a set of named choices.

Why this comes now

An array (Robot basics 2) has a length fixed when it is made: four wheels, two cameras. Some code cannot know the length in advance. A pre-match health check does not know how many problems it will find, and a mechanism may have several requests active at once. Team code uses an ArrayList for the first and an EnumSet for the second.

You will run lessons/ListsPractice.java from the home-java-starter folder you already have, in a second VS Code window, then return to your robot project.

See it

The program below collects health-check problems in a list, then keeps track of which requests are active in a set.

// Read the matching Java toolbox section, then do its change-and-predict task.
import java.util.ArrayList;
import java.util.EnumSet;

public class ListsPractice {
    enum Request { EJECT, RUN, HOLD }   // listed first = most important

    public static void main(String[] args) {
        // A list starts empty and grows each time you add to it.
        ArrayList<String> problems = new ArrayList<>();
        double batteryVolts = 12.1;
        boolean gyroConnected = false;
        if (batteryVolts < 12.3) {
            problems.add("Battery low: " + batteryVolts + " V");
        }
        if (!gyroConnected) {
            problems.add("Gyro not connected");
        }
        System.out.println(problems.size() + " problems");
        for (String problem : problems) {
            System.out.println("- " + problem);
        }
        System.out.println("First: " + problems.get(0));

        // A set of enum values: each value is either in the set or not.
        EnumSet<Request> active = EnumSet.noneOf(Request.class);
        active.add(Request.HOLD);
        active.add(Request.RUN);
        active.add(Request.RUN);            // already in the set: no change
        System.out.println("Active: " + active);
        System.out.println("Holding? " + active.contains(Request.HOLD));
        active.remove(Request.RUN);
        System.out.println("Active: " + active);
    }
}
PieceWhat it does
ArrayList<String> problems = new ArrayList<>();Makes an empty list. <String> says what it holds: text. The empty <> on the right repeats it for you.
problems.add(...)Puts one more item at the end. The list grows.
problems.size()How many items it holds now, like an array’s length.
problems.get(0)The item at position 0, the first one. Positions start at 0, as in an array.
for (String problem : problems)Visits every item in order, the same loop you used for arrays.
EnumSet.noneOf(Request.class)Makes an empty set that can hold Request values.
active.add, remove, containsPut a value in, take it out, ask whether it is in. Each value is either in the set or not; adding it twice changes nothing.

Two rules to remember. A list of numbers is written ArrayList<Double> or ArrayList<Integer>, with a capital letter, because lists hold objects and those are the object versions of double and int. And an EnumSet always lists its values in the order the enum declares them, whatever order you added them in.

Task. Predict each result before you run.

  1. HOLD was added before RUN, yet the set prints [RUN, HOLD]. Find the reason in the enum line.
  2. Change batteryVolts to 12.6. Run: one problem, and First: is now the gyro.
  3. Also change gyroConnected to true. Run. Expect 0 problems, then an error whose first line ends in java.lang.IndexOutOfBoundsException: Index 0 out of bounds for length 0. An empty list has no position 0.
  4. Fix it: print Ready when problems.isEmpty() is true, and the First: line only otherwise. Use an if and an else. Run again.
  5. Add active.add(Request.EJECT); before the last print. Predict where EJECT appears in the printed set, then run.

The team’s request pattern uses exactly this ordering: requests are declared from most to least important, so walking the set visits the most important active request first.

Explain the boundary
