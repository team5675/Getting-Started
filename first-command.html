Your first command: a simulated light

Start an action, observe its result, and see what happens when it ends.

← Getting Started · Practice after chapter 9

What you'll learn

Build a subsystem that remembers a light's state and a command that turns it on, then cleans up when it ends. The “light” is a boolean printed to the console. You do not need a robot, gamepad, or dashboard.

Before you start: open your learning-sandbox Command Robot project in WPILib VS Code 2026. Use the package frc.robot created by that template. Keep its generated Robot.java and scheduler call.

1. Make a subsystem

Create src/main/java/frc/robot/subsystems/PracticeLight.java and paste this complete file. The filename and public class name must match.

package frc.robot.subsystems;

import edu.wpi.first.wpilibj2.command.SubsystemBase;

// A pretend light: no physical hardware or vendor libraries needed.
public class PracticeLight extends SubsystemBase {
    private boolean on = false;

    public void setOn(boolean requestedState) {
        on = requestedState;
        System.out.println("Light on: " + on);
    }
}

extends SubsystemBase gives the class WPILib's subsystem behavior. The field on remembers state between method calls. private means other classes use our method to change it.

2. Make a command

Create src/main/java/frc/robot/commands/KeepLightOn.java and paste this complete file.

package frc.robot.commands;

import edu.wpi.first.wpilibj2.command.Command;
import frc.robot.subsystems.PracticeLight;

public class KeepLightOn extends Command {
    private final PracticeLight light;

    public KeepLightOn(PracticeLight light) {
        this.light = light;       // Remember the object passed to us.
        addRequirements(light);  // This command owns the light while running.
    }

    @Override
    public void initialize() {
        light.setOn(true);       // Called once each time this command starts.
    }

    @Override
    public void end(boolean interrupted) {
        light.setOn(false);      // Always clean up, including on cancellation.
    }

    // No execute() is needed: the boolean keeps its value between calls.
    // The inherited isFinished() returns false. Our caller adds a timeout.
}

final means this field keeps referring to the same light object. @Override lets Java check that we are supplying a method the parent class defines. Requirements prevent two commands from owning this light at once.

3. Connect it in RobotContainer

Open src/main/java/frc/robot/RobotContainer.java. Keep the class and existing setup. Add these imports below its package line, skipping any import already present:

import edu.wpi.first.wpilibj2.command.Command;
import frc.robot.commands.KeepLightOn;
import frc.robot.subsystems.PracticeLight;

Add this field inside the class, outside its methods:

private final PracticeLight practiceLight = new PracticeLight();

Replace the existing getAutonomousCommand() method with this one. Do not add a second copy:

public Command getAutonomousCommand() {
    // Start the light command, then interrupt it after about two seconds.
    return new KeepLightOn(practiceLight).withTimeout(2.0);
}

The generated Robot.autonomousInit() schedules the returned command. Its scheduler runs from robotPeriodic(). The timeout ends the inner command, so end() turns the light off. No busy waiting is needed.

4. Predict, run, and explain

  1. Predict which messages will print and how far apart they will be.
  2. Save all files, then run WPILib: Simulate Robot Code and select the Simulation GUI.
  3. In the Robot State panel select Autonomous so the simulator is enabled in autonomous mode. Watch the VS Code Terminal.
  4. After the two messages, choose Disabled. To repeat, switch from Disabled back to Autonomous.
What you should see
Light on: true
Light on: false

The second line appears about two seconds after the first. There is no field animation or physical light in this example.

Try one changeChange 2.0 to 4.0, restart the simulation, and repeat. Next, disable after about one second: cleanup should turn the light off early.
Explain it
  • Which class remembers whether the light is on?
  • What calls initialize() and end()?
  • Why does the light stay on without an execute() method?
  • Why must cleanup happen when you disable early too?
If nothing prints

Check that the build succeeded, that you replaced the existing getAutonomousCommand(), and that Robot.java still schedules it in autonomousInit(). Starting the simulator leaves it disabled; select Autonomous to run this action. Check the Terminal panel for the messages.
