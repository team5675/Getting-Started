Start and stop one action

Let the robot framework start a small action and clean up when it ends.

Today’s small goal

Turn a pretend light on for about two seconds, then off. Trace which method runs at each stage.

Before you start: Complete Lesson 7 and work with a mentor for this transition. Keep your original Command Robot template. No physical light or gamepad is required.

Allow 45–75 minutes with a mentor. This is a planning estimate, not a time limit. Pauses and questions count as learning.

1. Two jobs, two classes

A subsystem groups the state and operations for one part of a robot. A command describes an action using a subsystem. In this practice example, the subsystem stores a boolean called on. The command changes it at the start and end of an action.

The scheduler is framework code that starts and stops commands. You will give it an action to run; you do not write a loop that waits two seconds.

2. Add the light subsystem

  1. In Explorer, expand src/main/java/frc/robot.
  2. Open its subsystems folder, or create that folder if missing. Create PracticeLight.java inside it.
  3. Paste this complete file. Save and run WPILib: Build Robot Code. At this stage, it should build but will not print light messages yet.

Complete file: subsystems/PracticeLight.java

package frc.robot.subsystems;

import edu.wpi.first.wpilibj2.command.SubsystemBase;

public class PracticeLight extends SubsystemBase {
    private boolean on = false;

    public void setOn(boolean requestedState) {
        on = requestedState;
        System.out.println("Light on: " + on);
    }
}

import makes another class’s name available in this file. extends SubsystemBase means our class builds on WPILib’s subsystem class. The field and method inside should look familiar from PracticeCounter.

Calling setOn(true) stores true and prints it; setOn(false) stores false and prints it. The state stays in the field between calls. Nothing in this class drives real hardware.

3. Add the action

  1. Create KeepLightOn.java in the existing commands folder under frc/robot. Create the folder if necessary.
  2. Paste this complete file and save. Build again before changing anything else.

Complete file: commands/KeepLightOn.java

package frc.robot.commands;

import edu.wpi.first.wpilibj2.command.Command;
import frc.robot.subsystems.PracticeLight;

public class KeepLightOn extends Command {
    private final PracticeLight light;

    public KeepLightOn(PracticeLight light) {
        this.light = light;
        addRequirements(light);
    }

    @Override
    public void initialize() {
        light.setOn(true);
    }

    @Override
    public void end(boolean interrupted) {
        light.setOn(false);
    }
}
PieceWhat it means here
private final PracticeLight light;This field keeps a reference to the light object. Final means we do not replace that reference; the light’s own state can still change.
KeepLightOn(PracticeLight light)The constructor receives the light object the command will use. It does not create a second light.
this.light = light;The left side is this command object’s field; the right side is the constructor parameter. Store the received reference.
addRequirements(light);Tell the scheduler this command needs exclusive use of the light subsystem while it runs.
initialize()The scheduler calls this once when the action starts. It turns on the pretend light.
end(boolean interrupted)The scheduler calls this when the action ends. This example turns off the light whether it finished or was canceled.

You do not need execute() here: there is no changing output to recompute each cycle. The inherited isFinished() returns false, so this command will keep running until something ends it. We will add a timeout at the place that creates the action.

4. Connect one light in RobotContainer

Open RobotContainer.java, beside Robot.java. This class connects subsystems and commands in the generated template. Do not replace the entire file.

  1. Add these imports below the package line, skipping any already present:

Code to use

import edu.wpi.first.wpilibj2.command.Command;
import frc.robot.commands.KeepLightOn;
import frc.robot.subsystems.PracticeLight;
  1. Inside the RobotContainer class, add this field beside the existing fields, above the constructor. It creates one light object:

Code to use

private final PracticeLight practiceLight = new PracticeLight();
  1. Find the existing getAutonomousCommand() method using Ctrl+F. Replace only that complete method with the one below. Keep all other template code.

Code to use

public Command getAutonomousCommand() {
    return new KeepLightOn(practiceLight).withTimeout(2.0);
}

Read the return line in two parts: new KeepLightOn(practiceLight) creates an action using our existing light; .withTimeout(2.0) wraps it so it is ended after about two seconds. The returned command is scheduled by the template when Autonomous starts.

5. Run one action

  1. Save all changed files with File → Save All. Stop any previous simulation and launch WPILib: Simulate Robot Code.
  2. At startup, your earlier Lesson 7 messages may print. That is expected; they are separate from the light action.
  3. In the Simulation GUI, find Robot State. Select Autonomous. That mode runs the command returned by getAutonomousCommand. In versions with a separate enable control, enable Autonomous too.
  4. Watch the VS Code Terminal. Look for these two messages about two seconds apart:

Expected output — read this; do not paste it into Java

Light on: true
Light on: false

Autonomous means the robot program performs a scheduled action without a driver holding a button. Our action changes a boolean only. No robot shape, real lamp, or moving motor should appear.

6. Repeat, then change one thing

  1. Select Disabled, then Autonomous again. Each transition starts the action again.
  2. Change 2.0 to 4.0 in RobotContainer. Save, restart the simulation, then enable Autonomous. Predict how the gap between messages changes.
  3. On another run, select Disabled after about one second. The action should clean up early and print false.

The timeout interrupts the inner command when time runs out. Disabling also cancels the action. Our cleanup does not depend on which of those happened; both need the light turned off.

Nothing prints for the light
  1. Check the build succeeded and you restarted after saving.
  2. Check you selected Autonomous, not only launched the disabled simulator.
  3. Check you replaced the existing getAutonomousCommand, rather than adding an unrelated method.
  4. Ask a mentor to confirm the template’s Robot.autonomousInit schedules that returned command and robotPeriodic still runs the scheduler.
A package or class cannot be found

Check each file’s package against its folder: PracticeLight is in frc.robot.subsystems; KeepLightOn is in frc.robot.commands. Compare both imports in RobotContainer and save all files. Do not solve this by adding hardware vendor libraries; this example only uses WPILib.

Pause and check

Trace the action with your finger: RobotContainer creates one light; the command remembers it; initialize turns it on; end turns it off. Explain why creating the Java files alone did not start the action.

A good place to stop

This is a substantial new idea. Repeat it before moving to a larger project. When you can explain start and cleanup, try the last-year command reading with a mentor. The full swerve/vision project can wait.

Save your files. In your learning notes, write one thing you changed, what happened, and one question. Note the lesson number so you can resume here next time.
