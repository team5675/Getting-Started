Lesson 8 · Commands

Start and stop one action

Make an action run, finish and clean up.

One action over time

Use the simulation starter. Turn its pretend light on for two seconds, then change the duration and interrupt it. No physical light is connected.

TEAM TIP

Think about when it starts and stops.

A command describes a task over time. Read the example in order: start it, let it run, and find what makes it finish.

1. Meet the subsystem and command

Start with three jobs: the subsystem remembers whether the light is on; the command describes turning it on and off; the scheduler calls that command at the right times. A callback is a method the framework calls for you. The previous step, the inheritance example, showed what extends and @Override mean; look back at it if they feel new.

Press Ctrl+P and open src/main/java/frc/robot/subsystems/PracticeLight.java. It remembers a boolean. Then open src/main/java/frc/robot/commands/KeepLightOn.java. Its constructor receives that same light object and declares a requirement:

public KeepLightOn(PracticeLight light) {
    this.light = light;
    addRequirements(light);
}
@Override public void initialize() { light.setOn(true); }
@Override public void end(boolean interrupted) { light.setOn(false); }

A subsystem owns state and operations. A command describes an action over time. The scheduler calls initialize once when the command starts, and end when it finishes or is interrupted. The requirement prevents two commands from independently controlling the light at once.

this.light is the command’s field; the constructor parameter is the light object it was given. extends Command supplies framework behavior. @Override checks the callback spelling. The inherited isFinished returns false, so the action needs an external ending condition.

2. Find the timeout

In RobotContainer.java, find autonomousCommand. Its timed-light choice returns:

return lightCommand().withTimeout(2.0);

lightCommand() creates a fresh action. withTimeout wraps it in a two-second limit without waiting inside a Java loop. Robot.autonomousInit schedules the returned action; robotPeriodic runs the scheduler on each pass.

3. Run, change, interrupt

  1. Start the simulation. Choose Timed light in the browser station, then Autonomous. Expect Light on: true, then false roughly two seconds later.
  2. Disable and stop. Change only 2.0 to 4.0, save and restart. Repeat; predict the new gap.
  3. On another run, click Disabled after about one second. The light must turn off immediately.
  4. Inside end, add System.out.println("Interrupted: " + interrupted);. Save and restart. Compare timeout and Disable: both interrupt the inner light command, so both print true. That flag does not identify the cause.
The light never starts

Choose Timed light, not TrainingLine. Select Autonomous, and keep the browser focused; switching windows disables the model. Check the Terminal for a build error. Save and restart after edits.

4. Write your own timed command

Keep the working example above. Make a local backup (or a Git checkpoint if you have learned Git). Stop the simulation, then type this in the Terminal to add the two new files to your project:

.\robot lab8

It copies LightForSeconds.java into src/main/java/frc/robot/commands and LightCommandTest.java into src/test/java/frc/robot. It never replaces a file you already have, so running it twice is safe. If Gradle answers Task 'lab8' not found, your robot.cmd came from an earlier download: get the newer robot.cmd.

Complete initialize so it turns the light on, and end so it turns the light off whether completed or interrupted. The supplied timer restarts in initialize; isFinished compares elapsed time with the constructor's duration. Explain why a field stores the light object and why addRequirements is needed.

Stop simulation and check your command:

.\robot test --tests "frc.robot.LightCommandTest" --rerun-tasks

To try it in the browser, temporarily change the timed-light return inside RobotContainer.autonomousCommand to:

return new frc.robot.commands.LightForSeconds(light, 2.0);

Run, let it finish, repeat, then disable early. Compare with command-lab/answer after trying. Restore the original lightCommand().withTimeout(2.0) when continuing the core labs, or keep your experiment in its own saved folder (a Git branch also works after the Git lesson).

Your turn · choose a duration

Use 0.5 seconds and predict the ending time. Explain what should happen with zero seconds. A negative or nonfinite duration is rejected by the supplied constructor.

5. Make the next connection yourself

Lab 1 binds the light to an input. This is your next short task: hold Space to start it and release to stop it. Then save a backup or Git checkpoint.

In the real 2027 practice robot

This reviewed driver binding uses the same command lifecycle:

driver.a().whileTrue(drivetrain.applyRequest(() -> brake).withName("Brake"));

The A button starts a brake command on press and cancels it on release. Its subsystem and cleanup are more substantial than the pretend light, but the start/stop idea is the same. This is a reading excerpt; do not paste a hardware command into the teaching model. Source map.
