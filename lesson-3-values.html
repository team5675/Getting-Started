Use numbers with names and units.

Today’s small goal

Use numbers with names and units.

Use lessons/Values.java in the same Java foundations download at home and in class. Finish setup first.

TEAM TIP

Give the number a meaning.

For every variable, say what it represents and which units it uses. A name like distanceMeters tells the next programmer much more than x.

1. See it

A variable stores a value. double holds a number with a fractional part, int a whole number, boolean true/false, and String text. The equals sign stores a value; it does not ask a question.

double speedMetersPerSecond = 1.5;
double seconds = 2.0;
double distanceMeters = speedMetersPerSecond * seconds;
System.out.println("Distance: " + distanceMeters + " m");

At a constant 1.5 meters each second for 2 seconds, distance is 3.0 meters. * multiplies. With text on either side, + joins the text and number for display. Put units in the name and output; Java does not know that this double represents meters.

2. Try it in Values.java

Replace the 0.0 placeholder in Values.java with the multiplication using both variable names. Then change seconds to 4.0, run, and predict 6.0 meters. Change speed to -0.5 and seconds to 2.0; the answer should be -1.0 meters, motion in the opposite direction.

Save with Ctrl+S. In the Terminal opened in home-java-starter, run:

& $javaForLessons .\lessons\Values.java

Expected output after the task, with the original inputs

Distance: 3.0 m

3. Check an edge case

Use speed 0.0 and time 5.0. Explain why the result is zero. Restore the original inputs before comparing with the supplied answer.

If you get stuck

Check the filename, save, and fix the first compiler error. Quotes, braces and capitalization matter. Compare your small edit with the example. After trying, open the matching file under answers in a separate editor tab; do not compile both copies together.

In the real robot · 2027Practice

Source map and exact reviewed versions · Private team repository; excerpts remain readable here.

The robot names every important number, just like your variables. Most of them live in one file, Constants.java, each with a comment saying what it is and what units it uses:

Reading example from src/main/java/frc/robot/Constants.java — do not paste

/** Speed multiplier while the slow-mode button (left bumper) is held. */
public static final double SLOW_MODE_SCALE = 0.35;

It’s the same pattern as double distanceMeters = 1.5;: a type, a name and a value. Three extra words make it a team-wide setting. public lets other files read it, static means there’s one copy for the whole program, and final means it can’t be changed while the robot runs.

The comment explains the number. A teammate can tune it by changing one line, then rebuilding and deploying the program. Editing the file does not change a running robot. Names in capital letters, like SLOW_MODE_SCALE, are a convention for these fixed settings.

From the team’s 2027 practice-bot code (repository 2027Practice, branch codex/camera-verification, October 2026). It is built with the 2027 test version of WPILib, so a few names differ from your 2026 tools. Read it; don’t paste it.
