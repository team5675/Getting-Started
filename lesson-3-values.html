1. See it

A variable stores a value. double holds a number with a fractional part, int a whole number, boolean true/false, and String text. The equals sign stores a value; it does not ask a question.

Part of a declarationMeaning
doubleThe type: a number that can have a fractional part.
speedMetersPerSecondThe name: how we refer to this stored value.
= 1.5Store the initial value 1.5. Later assignment can replace it.
double speedMetersPerSecond = 1.5;
double seconds = 2.0;
double distanceMeters = speedMetersPerSecond * seconds;
System.out.println("Distance: " + distanceMeters + " m");

At a constant 1.5 meters each second for 2 seconds, distance is 3.0 meters. * multiplies. With text on either side, + joins the text and number for display. Put units in the name and output; Java does not know that this double represents meters.

Different kinds of information

Read and predict this example first. In Part B you will write these ideas inside main, after the distance calculation; do not paste the declarations twice. Quotes mean literal text; an unquoted name asks Java for the stored value.

int runs = 1;
boolean ready = true;
String teamName = "WiredCats";
System.out.println("teamName"); // The literal word teamName.
System.out.println(teamName);   // The stored text WiredCats.
runs = runs + 1;                // Read 1, add 1, then store 2.
System.out.println(runs);
System.out.println(ready);

Assignment can replace a value after its declaration. Do not write int again when updating runs. A boolean describes a yes/no fact; a String holds text. Your earlier double can keep a fractional value.

If you get stuck

Java’s message starts with the file and the line number. Read the words after error:, fix only the first error, save, and run again.

variable runs is already defined in method main(String[])
The type word was written again on the update line. Declare once, int runs = 4;, then update without the type: runs = runs + 1;.
incompatible types: possible lossy conversion from double to int
A number with a decimal part is going into an int. Use double for measurements. Keep int for whole-number counts.
cannot find symbol and symbol: variable distanceMeter
The name is spelled or capitalized differently from its declaration. Copy the name from the line where you declared it.
cannot find symbol and symbol: variable WiredCats
Text is missing its quotes. Write "WiredCats".

Still stuck? Open answers/Values.java in a separate editor tab and compare it with yours, line by line. More error messages.

A robot also gives important numbers useful names. Its slow-mode setting is a double named SLOW_MODE_SCALE, with value 0.35. Notice the same type, name and value pattern you used.

In the real robot · 2027Practice

Source map and exact reviewed versions · Private team repository; excerpts remain readable here.

The robot names every important number, just like your variables. Most of them live in one file, Constants.java, each with a comment saying what it is and what units it uses:

Reading example from src/main/java/frc/robot/Constants.java — do not paste

/** Speed multiplier while the slow-mode button (left bumper) is held. */
public static final double SLOW_MODE_SCALE = 0.35;

It’s the same pattern as double speedMetersPerSecond = 1.5;: a type, a name and a value. Three extra words make it a team-wide setting. public lets other files read it, static means there’s one copy for the whole program, and final means it can’t be changed while the robot runs.

The comment explains the number. A teammate can tune it by changing one line, then rebuilding and deploying the program. Editing the file does not change a running robot. Names in capital letters, like SLOW_MODE_SCALE, are a convention for these fixed settings.
