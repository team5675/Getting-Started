Lesson 2 of 8 · Begin at your own pace

Run your first program

Make the computer print a message, change that message, and learn how to recover from a small error.

Today’s small goal

See your own message in the Terminal and explain which line produced it.

Before you start: Your learning-sandbox project from Lesson 1, open in WPILib VS Code 2026.

Allow 35–60 minutes. This is a planning estimate, not a time limit. Pauses and questions count as learning.

1. Read before editing

Open Robot.java with Ctrl+P. There is already a lot of code. Leave it in place. For now, you need two ideas: a class groups related code, and a method is a named block of instructions. The outer Robot class contains several methods. Curly braces { } mark where each block begins and ends.

Find public void robotPeriodic() using Ctrl+F to search this file. This method already exists in the template. We will add a different method above it. Its name, robotInit, tells WPILib where our one-time startup instructions go.

2. Add one small method

  1. Place the cursor on the blank line immediately above the existing @Override that belongs to robotPeriodic().
  2. Paste the complete block below onto that blank line. Keep the existing method below it. The new block must be inside the outer Robot class, not inside another method.
  3. If your prepared project already contains robotInit(), ask your mentor which existing startup lines to keep; add the print line inside that method rather than creating another copy.

Code to use

@Override
public void robotInit() {
    System.out.println("Hello, robot!");
}

@Override lets Java check that we are providing a method the framework recognizes. You do not need to memorize that word today. Keep its spelling and capitalization. The same is true of public void; we will explain methods more fully in Lesson 5.

3. Understand the message line

PieceRead it as
System.out.printlnPrint a line of text to the program’s output. Use this exact spelling.
( ... )The parentheses contain what we want to print.
"Hello, robot!"Text between straight double quotes. Java calls text a String. The quotes mark the text; they are not printed.
;The semicolon ends this Java statement, an instruction.
{ and }These surround the instructions belonging to the method. Do not replace them with parentheses.

Spaces inside the quotes are part of the message. Indentation outside the quotes makes the code easier for people to read. Java distinguishes uppercase and lowercase: System and system are different names.

4. Save, build, and run

  1. Press Ctrl+S. The unsaved-change dot on the file tab should disappear.
  2. Open the Command Palette with Ctrl+Shift+P. Choose WPILib: Build Robot Code. The Terminal fills with messages; the first build may take a while.
  3. Look for a successful build result. If it fails, stop here and read the first relevant error rather than launching simulation.
  4. Open the Command Palette again and choose WPILib: Simulate Robot Code. Select the Simulation GUI if prompted. Use this WPILib action rather than an ordinary Run triangle.
  5. Look in VS Code’s Terminal for the line below. You may also see many startup messages. Use the Terminal’s Find command if needed to locate Hello, robot!.

Expected output — read this; do not paste it into Java

Hello, robot!

The simulation window can remain Disabled. This lesson only prints during startup; no motor or field animation is expected. The program will stay running even after the message appears. A single print line does not mean the whole robot program exits.

5. Change it, then run the new version

  1. Change only the text inside the quotes to Hello from Team 5675!. Keep both quotes, the parentheses, and the semicolon.
  2. Save the file.
  3. Stop the old simulation: focus its running Terminal and press Ctrl+C. If it remains active, use the Terminal’s trash/kill control for that simulation task. Ask a mentor if you are unsure which terminal is running it.
  4. Use WPILib: Simulate Robot Code again. It builds the saved change and starts a new program. The old running program does not automatically change when you type.

Expected output — read this; do not paste it into Java

Hello from Team 5675!

6. Predict two lines

Inside robotInit(), add the second statement shown below, after the first. Predict which message appears first.

Code to use

@Override
public void robotInit() {
    System.out.println("Hello from Team 5675!");
    System.out.println("I changed my program.");
}

Run the new version: save with Ctrl+S, stop the previous simulation, then use Ctrl+Shift+P → WPILib: Simulate Robot Code. Watch the VS Code Terminal. These startup examples run while the simulator is disabled. Need the full steps?

Expected output — read this; do not paste it into Java

Hello from Team 5675!
I changed my program.

In this method, these instructions run in order from top to bottom. Printing twice does not require two methods.

7. Practice fixing one error

  1. Remove the semicolon from the end of the second print statement.
  2. Save and build. This time, expect the build to fail. The computer has not been damaged.
  3. Find the first error about your Java file. It may say a semicolon is expected. The reported location is where Java noticed trouble; sometimes the cause is on the line above.
  4. Put the semicolon back, save, and build again. Run only after it builds.
My message is missing or still has the old words

Confirm the tab is Robot.java in learning-sandbox, save it, and stop the previous simulation. Start a fresh simulation with the WPILib command. Look in the Terminal for that new run, not an earlier build tab. A failed build never runs your new code.

Java reports braces, duplicate methods, or illegal start

Check that you added one robotInit method above the existing robotPeriodic method, not inside it. There should be one opening and one closing brace for your added method. Use Ctrl+Z to undo the last edit if you cannot identify it. Show your file to a mentor rather than deleting braces at random.

Pause and check

Point to the exact text you changed. Explain why saving alone did not change the message from an already-running program. Show how you repaired the missing semicolon.

A good place to stop

If you can change a message, run the new version, and find its output, you have enough for today. Leave the corrected code saved. Next time, you’ll give a value a name.

Save your files. In your learning notes, write one thing you changed, what happened, and one question. Note the lesson number so you can resume here next time.
