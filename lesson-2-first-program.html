What does println change compared with print?

Compare your explanation

println ends the line. Two print calls can share one output line.

If you explained it confidently, skim the worked example and try Part B. Otherwise work through the whole lesson.

1. See it

A program is a sequence of instructions. This file contains one instruction that prints a line. Keep the outer class and main lines as supplied for now; they give Java its starting place.

// TASK: Run once. Then change only the message to Hello, WiredCats!
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
PAUSE & PREDICT

Change the message. Predict the result.

Which text do you expect to appear when you run this program? Try changing only the words between the quotation marks.

System.out.println prints a line. Parentheses contain what to print, straight quotes surround text, and the semicolon ends the instruction. Quotes are not printed. Capital letters matter: System is different from system.

// starts a comment for the reader; Java ignores the rest of that line. The braces { } mark a body of instructions. For this lesson, edit only inside main’s braces. You do not need to memorize the surrounding words yet.

2. Try it in HelloWorld.java

Run the file unchanged. Expect Hello, World!. Change only the words between quotes to Hello, WiredCats!, save and run again. Stop after this one line; Part B adds your second message.

Save with Ctrl+S. In the Terminal opened in home-java-starter, run:

.\run HelloWorld

Part B · make a change yourself

Your second message

In lessons/HelloWorld.java, write a second System.out.println below the first, still inside main. Choose a sentence about something you want to learn. Predict the two lines in order, save, and run. Change only your second sentence and check both lines again.

A hint after you try

Two println calls produce two lines. A missing semicolon is a syntax error, not a robot problem.

Save your prediction, actual output and explanation. This is practice, not a speed test.

3. Check an edge case

Remove the semicolon from your second print statement, save and run. Java should report an error such as ';' expected, rather than print your new program. Find the filename and line number in the first error. Put the semicolon back, save and run successfully. This is a syntax error: Java could not read an instruction. A wrong message that still runs is a different kind of mistake.

If you get stuck

Java’s message starts with the file and the line number. Read the words after error:, fix only the first error, save, and run again.

';' expected
The semicolon at the end of a println line is missing. Add ; after the closing ).
package system does not exist
system was typed with a small s. Write System.
unclosed string literal
A closing quote is missing. Text needs a straight " at both ends.
cannot find symbol and symbol: method printIn(String)
In println, the letters after print are a lowercase l and then n (“print line”), not a capital I and n.
The old message still prints
Save with Ctrl+S before you run.

Still stuck? Open answers/HelloWorld.java in a separate editor tab and compare it with yours, line by line. More error messages.

In the real robot · 2027Practice

Source map and exact reviewed versions · Private team repository; excerpts remain readable here.

A competition robot has no screen to watch, and printed lines scroll away in a console. So the real robot “prints” differently: it records each value under a name, many times a second. The records go into a log file and to the driver dashboard, where they can be graphed later.

Reading example from src/main/java/frc/robot/subsystems/vision/VisionSubsystem.java — do not paste

Logger.recordOutput("Vision/" + name + "/AcceptedCount", acceptedCount[i]);

Compare it with your println: there is a message (the name "Vision/" + name + "/AcceptedCount", built with + exactly like your text) and a value (how many camera sightings were accepted). Logger.recordOutput is a method call, like System.out.println. Lesson 5 explains method calls.

One more difference: the 2027 code has no robotInit(). Its start-up instructions go in the Robot() constructor (startup setup), which Part 2 of this guide explains. The supplied stable-2026 simulator also uses a constructor. Your first Java lessons use main; the project setup lesson explains the transition.
