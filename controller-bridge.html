From keys to a controller

Follow one input from your keyboard through WPILib to a field-relative speed.

What you already know

Finish Reading a controller and Lab 2. The browser now supplies a virtual Xbox controller on Driver Station port 0. Your bindings use the standard CommandXboxController API. You do not need a physical controller for this lesson.

1. Follow the connection

Open SimControls.java to read the supplied adapter. It writes a complete packet of axes, buttons and robot mode, then notifies the simulated Driver Station. RobotContainer has one CommandXboxController named driver. The scheduler polls its button triggers and the default command reads its axes each pass.

The adapter gives upward stick input a negative Y value; manualDriveCommand negates that reading once so W moves up on our drawing. Do not add another sign flip in StudentProgram. The XY vector receives a circular deadband, then diagonal normalization and slow scaling. These are separate operations.

2. Prove it after turning

  1. Use Teleop. Hold D briefly, release, then hold W. Confirm X increases, then Y increases.
  2. Turn about 90° with Q. Repeat D and W. The directions on your screen must remain right and up.
  3. Try A, S, W+D and Shift. Explain how the diagonal stays within the full translation speed.
  4. Release everything, disable, and re-enable. No old movement should resume. Switching windows disables the station; deliberately select Teleop again after returning.

3. Make a binding yourself

Lab 1’s B binding printed once on each press. This time, react to the press and the release. Add this inside StudentProgram.configure:

robot.driver.leftBumper()
        .onTrue(Commands.print("Slow mode held"))
        .onFalse(Commands.print("Slow mode released"));

Hold Shift (the left bumper) in the station: one line appears when you press and one when you let go, not one every loop. Slow mode still works, because a print command needs no subsystem. Predict what holding Shift for three seconds prints, then check. Compare with A/Space using whileTrue. Remove this experiment when you are done.

Why not paste the same axes into the real robot?

The classroom drawing puts field +X to the right and +Y up. A real driver often asks for forward and left relative to the driver's view, and the team drivetrain may apply operator perspective. Axis names alone do not specify that conversion. With a mentor, trace input → deadband → scale → coordinate mapping → drivetrain request in the reviewed team code. Keep targeting math in the blue field frame; do not add your own alliance heading flip.

A real controller also needs correct port assignment and verified button mapping. This browser adapter proves the software interface, not a particular USB device or real drivetrain response.

Connection to the 2027 practice code

The team’s driver.a().whileTrue(...) brake binding uses this same trigger concept. The mechanism and command requirement change; the press, release and interruption rules remain relevant. Read the pinned source map before comparing APIs.
