1. What the workbook is for

The lessons show you a new idea one step at a time. The workbook gives you more practice with the same idea, at home, at your own speed. Each file goes with one lesson. It has a warm-up to predict and run, a few short exercises, and a ★ challenge for anyone who wants more.

In the downloadWhat it is
src/main/java/frc/robot/practice/The practice files you open, run and change. One per lesson.
src/test/java/frc/robot/practice/The self-checks. They run your methods with test values and say which exercise still needs work. You don’t need to open them.
answers/Finished versions of each practice file. Look at them after you have tried. Comparing a working answer with your own is a good way to learn.
README.txtA short copy of these instructions.
build.gradle, robot.cmd and the rest of srcThe simulation starter’s own files. They let the practice files build and run their checks; you do not need to change them.

2. Extract the workbook project

  1. Download practice-workbook.zip.
  2. In File Explorer, right-click it and choose Extract All. In the box that asks where to put the files, replace the suggested path with C:\dev and click Extract. You now have C:\dev\practice-workbook. (If you keep the suggested path, you get a folder inside a folder with the same name. That still works: open the inner one.)
  3. Look inside C:\dev\practice-workbook. You should see build.gradle, robot.cmd, src and answers. Those four tell you that you are in the right folder.

The download is a complete copy of the simulation starter with the practice files already added, so there is nothing to copy between folders and your main sim-starter work stays separate. Keep it outside OneDrive, like sim-starter. Do not create a new WPILib template project.

3. Open it in VS Code

  1. In 2026 WPILib VS Code choose File → Open Folder.
  2. Pick C:\dev\practice-workbook, the folder that contains build.gradle, and click Select Folder.

4. Run a practice file

Practice files have their own main method, so they run directly. No simulator is needed. Most are plain Java; the Advanced 4 file also uses WPILib’s geometry classes, which your WPILib project already includes.

  1. Open src/main/java/frc/robot/practice/Practice09RobotLoop.java.
  2. Wait until Java has finished loading the project. The first time this can take a minute or two. Watch the bottom bar.
  3. Look just above public static void main. Small gray words say Run | Debug. Click Run.
  4. The output appears in the Terminal panel.
I don’t see Run | Debug

Wait a little longer: the words appear only after Java has loaded the project. Check that you opened the practice-workbook folder itself, not a folder above or inside it. You can also right-click inside the file and choose Run Java. If neither works, ask a mentor to check that the Java extensions included with WPILib VS Code are enabled.

5. Check your work

  1. Finish the exercises in one practice file.
  2. Near the top of that file, change CHECK_MY_WORK = false to CHECK_MY_WORK = true. Save.
  3. Choose Terminal → New Terminal and run .\robot test --tests "frc.robot.practice.*". Watch the Terminal.
You seeIt means
BUILD SUCCESSFULEvery check you switched on passed.
A line with FAILED, such as Check09RobotLoop > exercise1_loopsIn() FAILEDThat exercise isn’t right yet. The next lines give a hint, for example Exercise 1: 1 second is 50 loops. FAILED here means “not finished”; it doesn’t mean anything is broken.
A compile errorJava can’t read part of a file. Fix the line it names first, exactly as in Lesson 2.

For the full list, including checks that were skipped because you haven’t switched them on, open build/reports/tests/test/index.html from the Explorer in a web browser.

Two switches

CHECK_MY_WORK checks the exercises everyone does. CHECK_CHALLENGE checks the ★ challenge, which the files mark with the word CHALLENGE. Leave a switch false until you are ready; its exercise checks are then skipped instead of failing. Java still compiles every source file, so a missing brace or another syntax error can stop the build even with both switches off.

7. Working at different speeds

Programmers on the team start in different places. That’s expected.

  • New to programming: do the lesson first, then the matching practice file. Skip the ★ challenge if you like. Come back to a file later and do it again without looking at your old answer.
  • Programmed before: open the practice file before the lesson and predict what it prints. If you predict the output correctly and can say why, skim the lesson and go straight to the ★ challenge. Switch on CHECK_CHALLENGE to check it.
  • Working with a partner: one person predicts and explains, the other types. Swap every 10–15 minutes, whatever your experience.
Pause and check · a first-use demonstration

Run Practice09RobotLoop and find its output. Then, this one time, switch on CHECK_MY_WORK before doing any exercises and run the checks, to see what an unfinished check looks like. They should say FAILED with hints. Read one hint and explain which exercise it points to. After this, use the normal order from section 5: finish the exercises first, then check.

A good place to stop

The workbook is ready. Use it after each lesson, or any time you want a refresher. Your changes stay in C:\dev\practice-workbook.
