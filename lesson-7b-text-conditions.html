Is mode == "teleop" a safe way to test text in Java? And what is 7 / 2 when both numbers are ints?

Compare your explanation

No: == asks whether two names refer to the same String object; mode.equals("teleop") compares the letters. 7 / 2 is 3, because whole-number division drops the remainder, and 7 % 2 is that remainder, 1.

1. See it: two questions at once

Lesson 4 asked one question per if. Robot rules often need two: aim only when the robot is enabled and the target is in range. Three symbols combine yes/no answers, which Java calls boolean values.

SymbolSay itTrue whenExample
&&andboth sides are truetrue && false is false
||orat least one side is truetrue || false is true
!notthe answer after it is false!false is true
double distanceMeters = 3.0;
boolean enabled = true;
System.out.println(distanceMeters >= 2.0 && distanceMeters <= 4.5);
System.out.println(distanceMeters < 2.0 || distanceMeters > 4.5);
System.out.println(!enabled);
PAUSE & PREDICT

In range, out of range, or neither?

Predict the three lines for 3.0 m. Then predict them again for exactly 4.5 m, and for 5.0 m.

For 3.0 m it prints true, false, false. At exactly 4.5 m the answers are the same, because 4.5 <= 4.5 is true. At 5.0 m they become false, true, false. The first line asks “inside the range?”; the second asks “outside it?”, so for any distance exactly one of them is true.

Each side is a whole question. Write distanceMeters >= 2.0 && distanceMeters <= 4.5, naming the variable twice. The shortcut distanceMeters >= 2.0 && <= 4.5 and the maths-style 2.0 <= distanceMeters <= 4.5 do not compile.

2. See it: compare text with equals

A String is an object, like your Counter and Battery objects. Lesson 7’s optional experiment showed that two names can refer to one object or to two objects. For text, == asks “the same object?”, while equals asks “the same letters?”.

String start = "tele";
String mode = start + "op";
System.out.println(mode);
System.out.println(mode.equals("teleop"));
System.out.println(mode == "teleop");
PAUSE & PREDICT

Same letters, same object?

The variable mode holds the letters teleop. Predict all three lines before you read on.

It prints teleop, true, false. Joining start + "op" while the program runs builds a new String object. It has the same letters as "teleop", so equals says true, but it is a different object, so == says false. Text a robot program reads from a controller, a file or the network is always built while the program runs.

Why this is a trap. Two pieces of text typed directly in quotes can share one object, so == sometimes gives the right answer in a small test and the wrong one on the robot. Always compare text with equals. Numbers and booleans are not objects: compare those with ==, as in Lesson 4.

3. See it: whole-number division and remainder

When both numbers are ints, / gives a whole number and drops the remainder. % gives the remainder.

int totalSeconds = 140;
System.out.println(totalSeconds / 60);
System.out.println(totalSeconds % 60);
System.out.println(7 / 2);
System.out.println(7.0 / 2);

It prints 2, 20, 3 and 3.5. 140 seconds is 2 whole minutes with 20 seconds left over. In the last line, 7.0 has a decimal point, so Java divides with decimals. The robot loop page, coming up soon, uses % to do something on every 50th pass.

Your working file is lessons/TextAndConditions.java. Not in your lessons folder? Your folder came from an earlier download: add the new lesson files. It has three methods marked TODO and a main that prints their answers. Leave main and the self-check support unchanged until Part B.

If you get stuck

Java’s message starts with the file and the line number. Read the words after error:, fix only the first error, save, and run again.

illegal start of expression, pointing just after &&
The right side of && is not a whole question, as in distanceMeters >= 2.0 && <= 4.5. Name the variable again: distanceMeters <= 4.5.
bad operand types for binary operator '<='
Java cannot chain 2.0 <= distanceMeters <= 4.5. Ask two questions and join them with &&.
bad operand types for binary operator '||'
One = in mode = "disabled" tries to store text, which is not a question. Use mode.equals("disabled").
TRY AGAIN: stop for disabled text built from two pieces; expected true; got false
shouldStop compares text with ==. Use equals.
TRY AGAIN: too close at 1.99 m; expected false; got true
|| is used where both parts must be true. Every distance is at least 2.0 or at most 4.5, so the answer is always true. Use &&.
