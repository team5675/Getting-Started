Name the choices: enum and switch

Give each mode a name instead of a number.

Why this comes now

Lab 6 checks for a fault and Lab 7 gives a mechanism named states. Both are easier to read, test and log with an enum.

You will run lessons/StatePractice.java from the home-java-starter folder you already have, in a second VS Code window, then return to your robot project.

See it

An enum lists the permitted named choices. A switch selects the behavior for one choice. Meaningful names make it harder to confuse a mode with an arbitrary number. This is a plain-Java example, not a new robot framework.

public class StatePractice {
    enum Mode { DISABLED, MANUAL, AUTO }
    static String describe(Mode mode) {
        switch (mode) {
            case DISABLED: return "Stopped";
            case MANUAL: return "Driver input";
            case AUTO: return "Scheduled path";
            default: throw new IllegalArgumentException("Unknown mode");
        }
    }
    public static void main(String[] args) {
        System.out.println(describe(Mode.DISABLED));
        System.out.println(describe(Mode.MANUAL));
        System.out.println(describe(Mode.AUTO));
    }
}

Try it in StatePractice.java

  1. Open. Leave the robot project as it is. In VS Code choose File → New Window, then File → Open Folder and pick the home-java-starter folder from Lessons 2–7B (for example C:\dev\home-java-starter). No new download is needed. Folder missing? Lesson 1 shows how to get it. No run.cmd in it? Add the launcher to an older folder.
  2. Run it unchanged. Press Ctrl+P and open lessons/StatePractice.java. Choose Terminal → New Terminal in this window, then type:
    .\run StatePractice

    Expected output before you change anything

    Stopped
Driver input
Scheduled path
  3. Change, save, run again. Do the task below, save with Ctrl+S and run the same command.
  4. Return. When you have explained the result, close this window. Your robot project is still open in the other sim-starter window. Then press Next.

Task. Predict each result before you run.

  1. Change one label, for example "Stopped" to "Robot stopped". Run: only that line changes.
  2. Add a fourth choice, enum Mode { DISABLED, MANUAL, AUTO, PAUSED }, and one more line at the end of main: System.out.println(describe(Mode.PAUSED));. Do not add a case yet. Run.
  3. Expect three lines, then an error whose first line ends in java.lang.IllegalArgumentException: Unknown mode. No case matched PAUSED, so the default branch stopped the program instead of inventing a behavior.
  4. Add case PAUSED: return "Paused"; above the default line. Run again: the fourth line now reads Paused.

The real robot’s request/state choices can use enums too. For telemetry, explain which state was chosen rather than logging only an unexplained integer.

Explain the boundary

Why did PAUSED cause an error before you added its case? And why did adding PAUSED to the enum change nothing until main used it?
