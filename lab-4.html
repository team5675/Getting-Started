Before you start

Keep working in the same sim-starter folder, with your edits from Lab 3. Lost your work, or starting on a different computer? Stop the simulator and copy checkpoint 04 first; how checkpoints work shows which two files go where.

Do this lab in one sitting if you can. Save a backup before you change anything.

Make the edit

Your edit: Finish pose and the PathPlanner editor lab. In configure, add the callback wiring below. Read method references first. getPose reports field coordinates; the speed callbacks use robot-relative velocities. The supplied trainingPathConfig contains fictional model dimensions.

// All speed callbacks below use ROBOT-relative velocities.
// Pose remains in the fixed BLUE field frame.
AutoBuilder.configure(
        robot.drive::getPose,
        robot.drive::resetPose,
        robot.drive::getRobotRelativeSpeeds,
        (speeds, feedforwards) -> robot.drive.driveRobotRelative(speeds),
        new PPHolonomicDriveController(new PIDConstants(5, 0, 0), new PIDConstants(5, 0, 0)),
        robot.trainingPathConfig(),
        () -> false, // No alliance mirroring on this classroom grid.
        robot.drive);
// Our ideal velocity model does not use wheel feedforward voltages.
robot.markPathConfigured();

Run and observe

Use PathPlanner GUI 2026.1.2 and open this robot project’s root folder (the folder containing build.gradle) as described in the editor lab. Inspect TrainingLine: start (1,1), end (2,1), heading 0°, max speed 0.5 m/s. Leave the supplied path unchanged for this first run. Open TrainingLine.auto too: Reset Odometry is checked. The simulator loads this auto at startup; restart Java after editing it. Start Java, select TrainingLine in the station’s autonomous selector, then Autonomous. Expect the reset to (1,1), movement to about (2,1), then zero applied speed. The Java library loads the actual .path file.

Try the boundary

Disable, move in Teleop to an unexpected position, disable again and repeat Autonomous. It resets and follows the same path. Disable mid-path on a third run; it must stop. The classroom example intentionally keeps the fixed blue frame on both alliances. Real field mirroring and driver perspective are separate topics; do not add an alliance heading flip here.

Connection to the 2027 practice code

The real AutoRoutines connects PathPlanner to drivetrain callbacks and resets the starting pose. This model omits wheel dynamics, feedforward application and real odometry sensors, so its result does not validate real swerve tuning. Reviewed source map.
