Lesson 5 of 8 · Begin at your own pace

Use a method

Give a small task a name so you can use it without writing its instructions again.

Today’s small goal

Tell the difference between defining a method and calling it, then trace one input and one returned result.

Before you start: Lessons 2–4 feel familiar. You can find the braces belonging to robotInit().

Allow 35–50 minutes. This is a planning estimate, not a time limit. Pauses and questions count as learning.

← Make a decision · All lessons

1. You have already called a method

System.out.println("Hello"); calls Java’s print method. You supply text between parentheses; the method prints it. Now you’ll write a short method of your own.

A method definition gives the method a name and a body of instructions. A method call asks it to do that work. Defining a method does not automatically run it.

2. Define a method beside robotInit()

  1. Open Robot.java. Find the closing brace of your robotInit().
  2. Below that brace, on a blank line before the next existing method, add this new method. It stays inside the Robot class.
  3. Keep your existing robotPeriodic() and the rest of the template.

Code to use

private void printWelcome() {
    System.out.println("Welcome to programming practice.");
}

private means we will call this helper from within this class. void means it does not hand back a result value. printWelcome is our chosen name. Empty parentheses mean it needs no input values.

3. Call it from your startup method

Where this goes: open src/main/java/frc/robot/Robot.java. Replace only the robotInit() method you added earlier, from its @Override line through that method’s matching closing brace. Keep the rest of the file. Do not add a second robotInit().

Code to use

@Override
public void robotInit() {
    printWelcome();
    printWelcome();
}

Run the new version: save with Ctrl+S, stop the previous simulation, then use Ctrl+Shift+P → WPILib: Simulate Robot Code. Watch the VS Code Terminal. These startup examples run while the simulator is disabled. Need the full steps?

Expected output — read this; do not paste it into Java

Welcome to programming practice.
Welcome to programming practice.

Follow the first call: Java enters printWelcome, executes its print statement, then returns to the next line in robotInit. The second call repeats that work. There is one definition and two calls.

I see nothing, or the method name is underlined

If nothing prints, check that you actually put the calls inside robotInit. If the name is underlined, compare spelling and capitalization with the definition. If Java reports an illegal start, you may have put the entire definition inside robotInit. Move the helper outside that method’s closing brace.

4. Let a method receive a value

Replace the printWelcome definition with this version. Its parameter is the named input name, whose type is String.

Code to use

private void printWelcome(String name) {
    System.out.println("Welcome, " + name + "!");
}

Now replace the calls in robotInit(). Each quoted value you pass in is an argument.

Code to use

@Override
public void robotInit() {
    printWelcome("Morgan");
    printWelcome("Casey");
}

Run the new version: save with Ctrl+S, stop the previous simulation, then use Ctrl+Shift+P → WPILib: Simulate Robot Code. Watch the VS Code Terminal. These startup examples run while the simulator is disabled. Need the full steps?

Expected output — read this; do not paste it into Java

Welcome, Morgan!
Welcome, Casey!

During the first call, the parameter name holds “Morgan.” During the second, it holds “Casey.” Changing the method to need an input means the old empty call printWelcome(); is no longer sufficient.

5. Return a result you can use

When you are ready for another small step, add this second helper method beside printWelcome. It calculates a result instead of printing.

Code to use

private double doubleDistance(double meters) {
    return meters * 2.0;
}

The first double says what type of value comes back. The parameter meters is the input. * means multiplication. return hands the result to the caller and ends this method call.

Where this goes: open src/main/java/frc/robot/Robot.java. Replace only the robotInit() method you added earlier, from its @Override line through that method’s matching closing brace. Keep the rest of the file. Do not add a second robotInit().

Code to use

@Override
public void robotInit() {
    double result = doubleDistance(1.5);
    System.out.println("Result: " + result);
}

Run the new version: save with Ctrl+S, stop the previous simulation, then use Ctrl+Shift+P → WPILib: Simulate Robot Code. Watch the VS Code Terminal. These startup examples run while the simulator is disabled. Need the full steps?

Expected output — read this; do not paste it into Java

Result: 3.0
  1. The argument 1.5 becomes the parameter’s value.
  2. The method computes 1.5 × 2.0 = 3.0.
  3. That returned value is stored in result.
  4. The next statement prints the stored value.

A returned number is not automatically printed. If you removed the print statement, the calculation would still happen, but you would not see its result in the Terminal.

6. Your turn

Call doubleDistance with 2.0 and 0.5, storing each result in a different variable. Print both. Predict the values before you run.

One possible answer

Code to use

@Override
public void robotInit() {
    double firstResult = doubleDistance(2.0);
    double secondResult = doubleDistance(0.5);
    System.out.println(firstResult);
    System.out.println(secondResult);
}

Expected output — read this; do not paste it into Java

4.0
1.0
Pause and check

Point to one definition and one call. Explain which word names a parameter, which value is an argument, and where the returned number goes.

A good place to stop

It is fine to use the examples while explaining. Save both helper methods. In later lessons, they can remain in the file even when robotInit does not call them.

Save your files. In your learning notes, write one thing you changed, what happened, and one question. Note the lesson number so you can resume here next time.
