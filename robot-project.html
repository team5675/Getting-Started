Open your first robot project

Run real robot-framework code on your laptop.

Your next project

Finish the Java objects lesson first. This project uses the real WPILib command scheduler with an ideal motion model, logging and a browser control station. No robot, controller or GitHub account is required.

Download the simulation starter

1. Open the extracted project

  1. Use the same stable WPILib 2026.2.1 and Java 17 installation from Lesson 1.
  2. Extract All to a local folder such as C:\dev\sim-starter. Keep this robot project outside OneDrive. WPILib rejects projects stored there.
  3. In WPILib VS Code 2026 choose File → Open Folder. Open the folder containing build.gradle, gradlew.bat and src. Keep the Java foundations folder separately.
  4. Open Terminal → New Terminal. Select your installed Java 17 directory for Gradle:
$env:JAVA_HOME = 'C:\Users\Public\wpilib\2026\jdk'
& "$env:JAVA_HOME\bin\java.exe" -version
.\gradlew.bat build

Change that example path if you used a current-user install. The first build needs internet to fetch the pinned libraries. A successful build runs the supplied reference integration test. It does not mean you have completed the student TODOs.

2. Start the model

.\gradlew.bat simulateJava
  1. Wait for “WiredCats training ready” in the Terminal. Leave that terminal running.
  2. Open the local Simulation Station in a browser on this same computer. This address works only while your Java program is running.
  3. Leave it Disabled. X and Y should both be 1.00 and heading 0.00. This is a coordinate grid, not a competition field.
  4. To stop: click Disabled, return to the Terminal and press Ctrl+C. Save code before restarting. A running program does not automatically load an edit.
Troubleshooting the first run

Port 8767 busy: stop the previous training run. Unsupported Java: check JAVA_HOME; stable 2026 needs Java 17. Download failed: ask for network/setup help; do not change Java syntax or install an alpha. Page cannot connect: first confirm the simulation started successfully. The optional WPILib native GUI is not needed; the browser supplies simulated Driver Station data. Do not launch a second Driver Station.

What you just ran: WPILib is the supplied code that manages the robot program. Our model calculates pretend motion, and the browser station displays it and sends your input. Getting this working is today’s goal; you will learn its internal parts one at a time.

4. Constructor, helper and callback

public Robot() { /* setup happens once */ }

private void practice() {
    System.out.println("One startup calculation");
}

@Override
public void robotPeriodic() { /* repeated framework work */ }

This is a small reading sketch, not a replacement file. In the actual Robot.java, its constructor calls practice() explicitly. WPILib does not know that helper’s name. Later calculation lessons replace only that helper, keeping the constructor and scheduler intact.

extends LoggedRobot means Robot builds on an existing class. @Override asks the compiler to check a framework callback such as robotPeriodic. Our own private practice helper has no @Override. Read the inheritance example when those words are new.

Bridge to the 2027 robot

The practice bot also constructs its subsystems, calls the command scheduler repeatedly and starts an autonomous command when enabled. The hardware controller changes to SystemCore; Java objects and these responsibilities remain useful. Meet the controller. This download stays on Commands v2 and stable 2026; never run the 2027 importer on it.
