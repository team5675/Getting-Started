Build on a class: extends and @Override

Start from a class that already works, then replace one method.

Why this comes now

The next step, Lesson 8, writes a class that begins extends Command and marks its methods with @Override. This short example shows what those two words do before you meet them in robot code.

You will run lessons/InheritancePractice.java from the home-java-starter folder you already have, in a second VS Code window, then return to your robot project.

See it

A subclass starts from another class and can replace one of its methods. Here SimSensor starts from Sensor and supplies a different readValue result. @Override lets the compiler check that your method really replaces an inherited one. A spelling mistake should fail during compilation rather than silently creating an unused callback.

public class InheritancePractice {
    static class Sensor { int readValue() { return 0; } }
    static class SimSensor extends Sensor {
        @Override int readValue() { return 7; }
    }
    public static void main(String[] args) {
        Sensor sensor = new SimSensor();
        System.out.println(sensor.readValue()); // 7, using the subclass behavior.
    }
}

Try it in InheritancePractice.java

  1. Open. Leave the robot project as it is. In VS Code choose File → New Window, then File → Open Folder and pick the home-java-starter folder from Lessons 2–7 (for example C:\dev\home-java-starter). No new download is needed. Folder missing? Lesson 1 shows how to get it. No run.cmd in it? Add the launcher to an older folder.
  2. Run it unchanged. Press Ctrl+P and open lessons/InheritancePractice.java. Choose Terminal → New Terminal in this window, then type:
    .\run InheritancePractice

    Expected output before you change anything

    7
  3. Change, save, run again. Do the task below, save with Ctrl+S and run the same command.
  4. Return. When you have explained the result, close this window. Your robot project is still open in the other sim-starter window. Then press Next.

Change SimSensor.readValue to return 9 and predict the output. Misspell its method with @Override still present, compile, then repair it. In the robot project, KeepLightOn extends Command and overrides initialize/end; Robot extends LoggedRobot and overrides periodic/mode callbacks.

Explain the boundary
