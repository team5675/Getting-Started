Motor lab 2 · tune from evidence

Hold a speed

Make your roller hold 20 rps against a load, and choose kP from logged numbers.

What you already did

This lab continues your own MotorRoller.java from Motor lab 1, with your kS and kV, and uses the ideas from Motors 2. Same sim-starter project, same invented roller. Allow 60–90 minutes.

You will prove: your roller holds 20 rps, within 0.5 rps, never more than 1 rps over, and is back within 1 rps half a second after a load arrives. The check measures exactly those numbers.

1. Add this lab’s check

Make a backup or Git checkpoint. Stop the simulation, then type:

.\robot motors2

It adds one file, test/java/frc/robot/MotorLab2Test.java, and never replaces a file you already have. This lab’s TODOs are already in your MotorRoller.java, marked MOTOR LAB 2. If Gradle answers Task 'motors2' not found, add the motor lab folders.

2. TODO 1 · feedforward

In speedVolts, replace return 0.0; with the prediction from Motors 2:

double feedforward = KS_VOLTS * Math.signum(targetRps) + KV_VOLTS_PER_RPS * targetRps;
return feedforward;

speedVolts is static: it only does math with the numbers it is given, and it never touches a roller. That makes it easy to check: the test hands it numbers and compares the answer.

3. TODO 2 · a command that holds a speed

Replace the placeholder return in runAtSpeed:

return runEnd(() -> {
    this.targetRps = targetRps;
    setVolts(speedVolts(targetRps, getSpeedRps()));
}, () -> {
    this.targetRps = 0.0;
    setVolts(0.0);
}).withName("Hold " + targetRps + " rps");

Each lambda now has two statements, so it uses braces { }, like a small method. Every loop, the first one reads the measured speed and asks speedVolts what to do. this.targetRps is the roller’s field, logged as Training/Motor/TargetRps; plain targetRps is the method’s parameter, as in Lesson 7A. The end lambda clears the target and sets 0 V.

4. Run with feedforward only

In StudentProgram.configure, replace the ramp line with:

robot.driver.b().whileTrue(motor.runAtSpeed(20.0));

If you did Motor lab 1’s “Your turn”, put // in front of all four of its switch lines. This lab uses Object present as the roller’s load, and the switch would start a second command. The four lines should now look like this:

// new frc.robot.sim.SimLimitSwitch(0, () -> robot.input().objectPresent()); // simulation only
// edu.wpi.first.wpilibj.DigitalInput limitSwitch = new edu.wpi.first.wpilibj.DigitalInput(0);
// new edu.wpi.first.wpilibj2.command.button.Trigger(() -> !limitSwitch.get())
//         .whileTrue(motor.runAtVolts(4.0));

The last line starts with a dot because it continues the line above it: Java reads those two lines as one statement. If only the first three lines have //, Java stops at the fourth with illegal start of expression.

  1. Run the simulation in Teleop. Click the keyboard area and hold B for about three seconds with Object present clear.
  2. Keep holding B and press O once. In the keyboard area, O checks Object present without moving the focus, so B stays held. Hold B for two more seconds, then release it.
  3. Stop Java and graph TargetRps, SpeedRps and CurrentAmps under Training/Motor.

Use O, not the checkbox, while you hold B. A click moves the focus out of the keyboard area, the station lets go of B, and the command ends just as the load arrives. No “· O” beside Object present on your station? It came from an earlier download: update it.

Read the speed just before the load arrives, and the speed after it has settled with the load. Write both down. How close was your Motors 2 prediction? Look at the current too: what happens to it when the load arrives?

double error = targetRps - measuredRps;

6. Check your implementation

Disable and stop the simulation, then run:

.\robot test --tests "frc.robot.MotorLab2Test" --rerun-tasks

The check uses your KS, KV and KP. It tests feedforward and feedback math with numbers, then holds 20 rps and measures the three requirements: within 0.5 rps from 1 s to 2 s, never more than 1 rps over, and back within 1 rps 0.5 s after the load. If it fails, its message says which requirement and gives a hint. Compare with motor-lab-2/answer only after trying.

Your turn · notice a load from the current

In 2026 the team wrote code that watched a feeder motor’s current: about twice the usual current meant two game pieces at once, and the code briefly raised another mechanism’s speed target. Your roller can notice its load the same way. First, read CurrentAmps in your log with and without the load. Then add this inside configure:

new edu.wpi.first.wpilibj2.command.button.Trigger(() -> motor.getCurrentAmps() > 12.0)
        .onTrue(edu.wpi.first.wpilibj2.command.Commands.print("Load detected"));
  1. Hold B with no load. Does “Load detected” print in the Terminal anyway? Use the spin-up picture in Motors 1 to explain why.
  2. Change the code so it stays quiet while the roller speeds up, but still notices the load.
    Hint 1

    Join two questions with && from Lesson 7B: one about the current, and one about how close the speed is to 20, using Math.abs(motor.getSpeedRps() - 20.0).

    Hint 2

    If it still prints once at the start, the condition is true for only a loop or two. new Trigger(...).debounce(0.1) makes a Trigger that turns true only after the condition has stayed true for 0.1 seconds. Put .debounce(0.1) before .onTrue(...).

  3. Is 12.0 a good threshold for your roller? Use your logged currents to justify the number.
Before you move on

Show your kP table and the passing check. Explain why feedforward alone dropped under the load, why your kP still leaves a small error, and what went wrong at 4.0.

Record one prediction, the actual result and your explanation in learning-notes.txt.
