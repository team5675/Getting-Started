Ask now: lambdas, suppliers and method references

Hand over instructions to run later, not a value to keep.

Why this comes now

Labs 4 and 5 give WPILib small pieces of code to call later: robot.drive::getPose, (speeds, feedforwards) -> … and Commands.defer(() -> …). This page explains the -> arrow, the :: double colon and callbacks that receive values.

You will run lessons/LambdaPractice.java and lessons/CallbackPractice.java from the home-java-starter folder you already have, in a second VS Code window, then return to your robot project.

See it

A lambda is a short unnamed function. () -> controls.value means “read this when asked,” not “remember the number now.” Compare saved: an ordinary double holds a copy of the number taken once, so it keeps that value even after the field changes. A supplier is an object whose getter provides a value; our DoubleSupplier uses getAsDouble. The long java.util.function name identifies the supplied Java type, not another method you need to write. A method reference such as controls::show names an existing method that can be called later.

public class LambdaPractice {
    static class Controls {
        double value = 1.0;
        void show() { System.out.println(value); }
    }
    public static void main(String[] args) {
        Controls controls = new Controls();
        double saved = controls.value; // a copy of the number, taken now
        java.util.function.DoubleSupplier live = () -> controls.value;
        controls.value = 2.0;
        System.out.println(saved);              // 1.0
        System.out.println(live.getAsDouble()); // 2.0
        Runnable display = controls::show;
        display.run(); // 2.0
    }
}

Callbacks that receive values

The lambdas above take nothing in: () -> has empty parentheses. Lab 4 also hands PathPlanner a lambda that receives values: (speeds, feedforwards) -> robot.drive.driveRobotRelative(speeds). A lambda used like this is a callback: you write what should happen, and other code decides when to call it and supplies the values.

// Read the matching Java toolbox section, then do its change-and-predict task.
public class CallbackPractice {
    // A pretend path follower. Each loop it works out one speed and hands it
    // to the callback it was given. The follower decides WHEN to call it;
    // your lambda decides WHAT happens with the speed.
    static void followPath(java.util.function.DoubleConsumer output) {
        double[] speeds = {0.25, 0.5, 0.25};
        for (double speed : speeds) {
            output.accept(speed);
        }
    }

    // The same follower, but each loop it hands over TWO values: a speed and
    // an extra voltage. Your lambda receives both; it may use only one.
    static void followPathWithExtra(java.util.function.BiConsumer<Double, Double> output) {
        double[] speeds = {0.25, 0.5, 0.25};
        for (double speed : speeds) {
            output.accept(speed, 0.4);
        }
    }

    public static void main(String[] args) {
        // One value in: speed is the parameter name; the follower supplies it.
        followPath(speed -> System.out.println("drive " + speed));
        // Two values in: both names go inside the parentheses.
        followPathWithExtra((speed, extraVolts) -> System.out.println("drive " + speed));
    }
}

Read each lambda from left to right. Before the arrow are names for the values that come in: speed for one value, (speed, extraVolts) for two. You choose those names; the follower supplies the values each time it calls. After the arrow is what happens with them. These callbacks return nothing. DoubleConsumer and BiConsumer<Double, Double> are the supplied Java types for “receives one number” and “receives two numbers”; you do not write those types in Lab 4.
