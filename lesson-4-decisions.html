Make a decision

Use a true-or-false question to choose which instructions run.

Today’s small goal

Predict and test what happens below, at, and above a boundary.

Before you start: You can declare a variable, print it, and restart a saved program from Lesson 3.

Allow 30–45 minutes. This is a planning estimate, not a time limit. Pauses and questions count as learning.

1. Start with a question you can answer

Suppose a practice activity uses the message “Too close” when a made-up distance is less than 1 meter. We will type that distance ourselves. No sensor is connected, and this is not a real robot safety threshold.

The question is distanceMeters < 1.0. The < symbol means “less than.” If the distance is 0.5, the answer is true. If it is 2.0, the answer is false.

2. Write both outcomes

Where this goes: open src/main/java/frc/robot/Robot.java. Replace only the robotInit() method you added earlier, from its @Override line through that method’s matching closing brace. Keep the rest of the file. Do not add a second robotInit().

Code to use

@Override
public void robotInit() {
    double distanceMeters = 0.5;

    if (distanceMeters < 1.0) {
        System.out.println("Too close");
    } else {
        System.out.println("Clear");
    }

    System.out.println("Check complete");
}

Read the method one step at a time:

  1. Store 0.5 in distanceMeters.
  2. if (...) asks the question in parentheses.
  3. If the answer is true, run the first braced block.
  4. else supplies the other block, used when the answer is false. For this if/else pair, only one of those blocks runs.
  5. After that pair, continue with Check complete, which is outside both branches but still inside the method.

Run the new version: save with Ctrl+S, stop the previous simulation, then use Ctrl+Shift+P → WPILib: Simulate Robot Code. Watch the VS Code Terminal. These startup examples run while the simulator is disabled. Need the full steps?

Check complete

4. A one-character change matters

Change < to <=, which means “less than or equal to.” Keep the distance at 1.0. Predict, then test: it should now print Too close.

SymbolMeaningExample question
<Less thanIs 0.9 less than 1.0?
>Greater thanIs 3 greater than 2?
<=Less than or equal toIs 1.0 at most 1.0?
>=Greater than or equal toIs 3 at least 3?
==Equal, for the primitive values used hereIs a whole-number count equal to 3?
!=Not equalIs a whole-number count different from 3?

= assigns a value; == compares values. They have different jobs. Comparing text Strings has its own rule; we are not doing that in this lesson.

5. Make your own small check

Use int practiceRuns = 2;. If the count is at least 3, print Ready for a review. Otherwise, print Try another practice run. Keep a second message outside the branches: Decision finished.

Hint: choose the comparison first

“At least 3” means practiceRuns >= 3. Put that question in the if parentheses. Each message belongs inside one branch; the final message belongs after the entire if/else.

One possible answer

Code to use

@Override
public void robotInit() {
    int practiceRuns = 2;
    if (practiceRuns >= 3) {
        System.out.println("Ready for a review");
    } else {
        System.out.println("Try another practice run");
    }
    System.out.println("Decision finished");
}

Test counts 2, 3, and 4. The number is a coding example, not a score or a rule about when a real person is ready.

If the wrong branch runs

  1. Read the exact value you assigned for this run.
  2. Translate the symbol into words: less than, at least, or equal?
  3. Check there is no semicolon immediately after if (...). The opening brace should follow the condition.
  4. Check that the print statements are inside the intended braces.
Pause and check

Without running first, explain what the original distance example does at exactly 1.0. Then describe what changes when you use <= instead of <.

A good place to stop

You can now edit, run, store information, and choose between two outcomes. That is a useful first-hours milestone. Take a break or try one independent variation before starting Lesson 5 in another session.

Save your files. In your learning notes, write one thing you changed, what happened, and one question. Note the lesson number so you can resume here next time.
