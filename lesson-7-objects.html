1. See it

Imagine two separate counters. Pressing the first counter’s button should change only its number. A class describes how a counter works; an object is one counter created from that description. Each new Counter() creates another object. Its number is stored in a field, which remembers its value between calls.

Your working file is lessons/ObjectsPractice.java. It already has two counters and an inner class named Counter. Find void increment() and void reset(). You will replace only their TODO bodies. For this first step, leave the constructor, getValue, main and self-check support unchanged. Part B will add calls inside main.

Read a smaller counter example · do not paste it into the starter

This reading example shows the same idea with one increment. The downloaded file puts Counter inside ObjectsPractice and writes the constructor explicitly, so the whole exercise stays in one Java file. Those structural differences are supplied for you.

class Counter {
    private int value = 0;
    public void increment() { value++; }
    public int getValue() { return value; }
}

// Inside main:
Counter first = new Counter();
Counter second = new Counter();
first.increment();
System.out.println(first.getValue());  // 1
System.out.println(second.getValue()); // 0

Here private protects the field from direct edits by other classes; callers use the public methods. new Counter() calls a constructor to prepare an object. If you do not write a constructor here, Java supplies a no-argument one. A constructor has the class name and no return type. The robot project will use a constructor named Robot().

Optional extension · one object, two names

One object, two names

After completing the core task, save a backup. In ObjectsPractice.main, replace only the counter creation, increment and value-print lines with this experiment. Keep the existing Counter class and the initial check-handling block. Predict before running, then undo the experiment to restore the two independent counters.

Counter first = new Counter();
Counter second = first;
second.increment();
System.out.println(first.getValue());  // 1: both names refer to the same object.
System.out.println(second.getValue()); // 1

Assignment copied a reference, not a whole Counter. Draw two arrows pointing at the same box. Calling new twice instead gives two boxes.

Optional extension · a field remembers; a local variable starts again

Remembered state versus temporary work

Create a new Scratch.java file in the lessons folder with the complete example below. Run it with the same Java command, replacing ObjectsPractice.java with Scratch.java. Its main method calls each experiment twice on one object.

class Scratch {
    public static void main(String[] args) {
        Scratch example = new Scratch();
        example.fieldExample();
        example.fieldExample();
        example.localExample();
        example.localExample();
    }
    private int remembered = 0;
    public void fieldExample() {
        remembered = remembered + 1;
        System.out.println(remembered);
    }
    public void localExample() {
        int temporary = 0;
        temporary = temporary + 1;
        System.out.println(temporary);
    }
}

The field example prints 1 then 2. The local example prints 1 then 1: each call creates a new temporary variable. Robot counters and heading-trust flags need remembered state.

In increment(), add one to the existing value field using value = value + 1;. In reset(), assign zero. Do not declare a new local value or make the field static: each counter needs its own remembered number. In the real robot · 2027Practice

Your Counter remembered a number between method calls. The robot has a small class built the same way. It remembers whether the robot’s heading can be trusted, so the camera knows when to correct the position:

Reading example from src/main/java/frc/robot/subsystems/vision/PoseSeedTracker.java — do not paste

public final class PoseSeedTracker {
  /** True once a MegaTag1 fix has lined the heading up with the field. */
  private boolean headingTrusted = false;

  /** True when we'd like a fresh MegaTag1 fix (only used while disabled). */
  private boolean refreshWanted = true;

  // ... more fields and methods ...

  public boolean headingTrusted() {
    return headingTrusted;
  }
}

Where one object is created, in VisionSubsystem.java — do not paste

private final PoseSeedTracker seed = new PoseSeedTracker();

Find the same parts as in your counter: private fields that keep their values between calls, and a getter, headingTrusted(), that reports one of them. Other methods change the fields. For example, disabling the robot asks for a fresh camera fix without forgetting the heading.

This class uses no robot hardware, only plain Java. So the team’s tests can walk through a whole match in a few lines, with no robot attached.
