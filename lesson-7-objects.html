1. Why another file?

So far, most examples ran inside one startup method. A robot program needs groups of related information and actions. A class describes one kind of thing. An object is one particular instance made from that description.

Our class describes a counter. Each counter object will hold its own number, increase it, and tell us its current value. This uses the variables and methods you already practiced.

2. Create the class file

  1. In VS Code Explorer, find the folder containing Robot.java: src/main/java/frc/robot.
  2. Right-click that folder and choose New File. Name it PracticeCounter.java, matching the capitalization below.
  3. Paste the entire file below and save. If the editor generated any content first, replace it; do not duplicate the package or class declaration.

Complete file: PracticeCounter.java

package frc.robot;

public class PracticeCounter {
    private int count;

    public PracticeCounter(int startingCount) {
        count = startingCount;
    }

    public void addOne() {
        count = count + 1;
    }

    public int getCount() {
        return count;
    }
}

3. Read it in small pieces

PieceWhat it contributes
package frc.robot;Names the group this class belongs to. It matches our folder and the package of Robot.java.
public class PracticeCounterDefines the class; its name matches the filename.
private int count;A field: stored information belonging to each object. It is outside the methods.
public PracticeCounter(int startingCount)The constructor: setup performed when an object is created. Its name matches the class and has no return type.
count = startingCount;Copies the input into that object’s field.
public void addOne()A method that changes the field but returns no value.
public int getCount()A method that returns the current whole-number count.

private means other classes cannot reach directly into this field. Our public methods are the intended way to use the object. That gives us a clear place to explain and manage changes.

4. Create and use two objects

Return to Robot.java. Keep PracticeCounter.java in its own tab/file.

Where this goes: open src/main/java/frc/robot/Robot.java. Replace only the robotInit() method you added earlier, from its @Override line through that method’s matching closing brace. Keep the rest of the file. Do not add a second robotInit().

Code to use

@Override
public void robotInit() {
    PracticeCounter first = new PracticeCounter(0);
    PracticeCounter second = new PracticeCounter(10);

    first.addOne();
    first.addOne();
    second.addOne();

    System.out.println("First: " + first.getCount());
    System.out.println("Second: " + second.getCount());
}

new PracticeCounter(0) constructs an object, passing 0 to its constructor. The variable first refers to that object. The next line creates a separate object starting at 10.

In first.addOne(), the dot means “call this method on the object named first.” The empty parentheses mean that call supplies no inputs. It changes first’s field; it does not change second’s field.

Run the new version: save with Ctrl+S, stop the previous simulation, then use Ctrl+Shift+P → WPILib: Simulate Robot Code. Watch the VS Code Terminal. These startup examples run while the simulator is disabled. Need the full steps?

Expected output — read this; do not paste it into Java

First: 2
Second: 11

5. Field or local variable?

A local variable declared inside a method exists for that call’s work. A field belongs to the object and can retain its value between method calls.

Our count field is declared once per counter object. If you put int count = 0; inside addOne(), you would create a new local variable on every call. It would hide the field there, so the field read by getCount() would not increase.

Optional experiment: see that difference

In the sandbox only, add int count = 0; as the first line inside addOne. Predict the output and run. It should print First: 0 and Second: 10 because the local count changed but the fields did not. Remove that local declaration, run again, and restore First: 2 and Second: 11 before continuing.

6. Try one variation

Create a third object named third, starting at 5. Increase only third once and print its value. Keep the first and second objects too. Predict all three results.

Hint and expected result

Add these statements inside robotInit(), after the other print statements

PracticeCounter third = new PracticeCounter(5);
third.addOne();
System.out.println("Third: " + third.getCount());

The additional output is Third: 6; the earlier outputs remain 2 and 11.

If Java cannot find the class

Check the filename, class name, and capitalization: all say PracticeCounter. Check that the file is beside Robot.java, its first line says package frc.robot;, and both files are saved. Do not paste the complete class definition into robotInit.

Pause and check

Point to the class definition, a constructor call, a field, and a method call. Explain why increasing first does not increase second.
