Save and share your work

Use Git to keep useful checkpoints and let a teammate review what changed.

One practice branch, small checkpoints

Activities 0–9 build on each other. Use yourname/programming-practice throughout. Ask your mentor for a training repository and starting version; do not use the competition repository unless directed.

  1. Before editing, check the branch name at the bottom-left of VS Code.
  2. Make one small change and run the relevant simulation check.
  3. Open Source Control and click each changed file to read the diff. Stage only the files you intended to change.
  4. Commit with a message explaining the change, then push. Check that the commit appears on your branch on GitHub.

A commit saves a local checkpoint. A push shares commits. A pull request lets someone review proposed changes. A merge brings reviewed changes into another branch.

First-time setup

If Git asks for your name or email, work with your mentor to set your chosen commit identity. A GitHub-provided private commit email can be used. If pushing asks you to sign in, follow VS Code's GitHub sign-in flow; do not put passwords or access tokens into project files.

Keep the learning evidence

For an observation-only activity, update learning-notes.md and commit it:

Activity:
I expected:
I observed:
My explanation:
One question I still have:

Review together

At Activity 4, open one draft PR from your practice branch. Continue pushing later activities to that branch; the PR updates with them. Ask for feedback along the way. At Activity 9, mark it ready for review. The mentor decides whether to merge, keep it as a learning record, or move selected work elsewhere.

Suggested PR description: what changed, how you checked it, and one question for the reviewer. Review the code and explanation; nobody needs to invent a correction just to make a review count.

If something goes wrong

  • Unexpected changes: read the diff before staging. Use Undo for a recent edit. Ask for help before discarding files.
  • Push rejected or merge conflict: stop and ask a mentor to help reconcile the histories. Do not force-push to make the message disappear.
  • Hundreds of generated files: check the project's ignore rules. Do not commit build/, .gradle/, secrets, or robot log files.
