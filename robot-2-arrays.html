1. Four of the same thing

Our swerve robot has four wheels, and each one has a speed. You could make four variables: frontLeftSpeed, frontRightSpeed and so on. But then every check has to be written four times. And a robot with three cameras needs three copies of every camera check.

An array holds many values of the same type under one name. Each value has a numbered slot, its index.

2. Make an array and read from it

Where this goes: in Robot.java, replace only your practice() method.

Code to use

private void practice() {
    double[] wheelSpeeds = {2.1, 2.4, 1.9, 2.6}; // m/s: front-left, front-right, back-left, back-right
    String[] names = {"Front left", "Front right", "Back left", "Back right"};

    System.out.println("There are " + wheelSpeeds.length + " wheels");
    System.out.println("Front right: " + wheelSpeeds[1] + " m/s");

    for (int i = 0; i < wheelSpeeds.length; i++) {
        System.out.println(names[i] + ": " + wheelSpeeds[i] + " m/s");
    }
}
PieceWhat it does here
double[] wheelSpeedsThe square brackets mean “an array of doubles.”
{2.1, 2.4, 1.9, 2.6}The starting values, in order.
wheelSpeeds[1]The value in slot 1: the second one, 2.4.
wheelSpeeds.lengthHow many slots: 4. No parentheses: it’s a stored number, not a method.
names[i] and wheelSpeeds[i]Two arrays in the same order. One index finds matching values in both.

3. Too fast: slow every wheel by the same fraction

Sometimes the drive code asks one wheel to go faster than its motor can. If only that wheel is slowed down, the wheels no longer agree and the robot drives in the wrong direction. The fix is to slow every wheel by the same fraction. The robot then moves in the right direction, just slower. Advanced 2 shows this inside the swerve code.

Where this goes: inside practice(), after the for loop and before the method’s closing brace.

Code to use

double fastest = 0.0;
for (double speed : wheelSpeeds) {
    if (Math.abs(speed) > fastest) {
        fastest = Math.abs(speed);
    }
}
System.out.println("Fastest: " + fastest + " m/s");

double maxSpeed = 2.0; // pretend the motors can't go faster than this
if (fastest > maxSpeed) {
    double scale = maxSpeed / fastest;
    for (int i = 0; i < wheelSpeeds.length; i++) {
        wheelSpeeds[i] = wheelSpeeds[i] * scale;
    }
}
for (int i = 0; i < wheelSpeeds.length; i++) {
    System.out.println(names[i] + ": " + String.format("%.2f", wheelSpeeds[i]) + " m/s");
}

The first loop is a for-each loop. Read for (double speed : wheelSpeeds) as “for each speed in wheelSpeeds.” It hands you each value in turn. Use it when you only need the values. Use the counting for loop when you need the index, for example to change a slot with wheelSpeeds[i] = ....

Expected output — read this; do not paste it into Java

Fastest: 2.6 m/s
Front left: 1.62 m/s
Front right: 1.85 m/s
Back left: 1.46 m/s
Back right: 2.00 m/s

Every speed was multiplied by 2.0 / 2.6 ≈ 0.77. The fastest wheel is now exactly 2.00, and the others keep the same proportions.

4. Try one variation

Add a line that prints wheelSpeeds[4]. Predict what happens before you run.

What happens, and why it matters

The program stops with an error that includes ArrayIndexOutOfBoundsException: Index 4 out of bounds for length 4. Slot 4 doesn’t exist; the last one is 3. On a real robot, an error like this stops the robot program, and the robot stops driving until the code restarts. That’s why loops use i < wheelSpeeds.length and not <=. Delete the line before continuing.

The first excerpt is an array of objects. Each new CameraConfig(...) holds one camera’s name, its AprilTag pipeline number and an optional mount.
