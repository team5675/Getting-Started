Programming with the WiredCats ↗MENTOR GUIDE · OCTOBER 15, 2026

Help a new programmer find their footing

One route at home and in class. Give each learner time to predict, try, explain and repeat.

What is ready

Lessons 1–7B use the same plain-Java download. After Lessons 7, 7A and 7B, set up the simulation starter, then teach one command. Six simulation checkpoints connect buttons, default commands, logs, paths, events and fault recovery. No gamepad or robot is required.

The stable teaching stack is WPILib 2026.2.1, Java 17, AdvantageKit 26.0.2, PathPlanner 2026.1.2 and Commands v2. The SystemCore alpha bench is a separate mentor project. The 2027 game is unknown.

Before class

  1. On a clean Windows student account, install the approved stable tools, locate Java 17, extract the Java ZIP and print Hello, World! using only Lessons 1–2. Also try the school's restricted account.
  2. Extract sim-starter outside OneDrive, build it and run .\robot. Open http://127.0.0.1:8767/. Confirm the timed light starts in Autonomous, ends after two seconds and ends early on Disable.
  3. Walk through all six checkpoints with one student. Open the PathPlanner project in GUI 2026.1.2, save/preview it, and check the path and named event. Native GUI acceptance and a fresh installer/VS Code walkthrough remain manual checks.
  4. Choose a student Git repository and grant access before assigning pushes. Private real-robot source links are optional; every required excerpt is included on the page.
  5. For students learning independently, use AdvantageScope from the stable tools and the public five-row log extract. For a guided team session, provide the local v11 viewer from the mentor's docs/tools folder. Start with the guided historical log exercise, then use each student's own simulation log in Lab 3. Raw match logs and the viewer are not part of the public website download.

Plan around 45–75 minutes, with no deadline to finish a topic. Pair students, swap the keyboard, and ask each learner to make a prediction. Use learning-notes.txt to record the last working result and next question after a break.

Use the checks honestly

Actual Java 17 validation ran all 14 home answer programs and four extra boundary cases. The optional workbook's 52 enabled checks pass on answers and fail on unfinished exercises. Native desktop integration tests pass for the stable simulator and completed student program, covering interruption, normalized inputs, slow mode, fault recovery, real PathPlanner execution, repeated events and early disable. These checks establish software behavior in an ideal model; they do not establish real robot motion, CAN health, camera timing or SystemCore performance.

.\robot test checks the supplied teaching infrastructure with a completed reference implementation. Only after Lab 6, run .\robot test -PcheckStudent --rerun-tasks to test the student's current program. Earlier unfinished checkpoints are expected to fail that final check. GUI testing and a clean laptop installation are separate acceptance steps. Both test modes run from a test-owned deploy copy under build/simulation-test, so neither overwrites the student’s source or PathPlanner files.

Make the exercise, not the answer, the goal

  1. Run the last working example and explain one line.
  2. Predict one result before editing.
  3. Change one thing, run it and compare.
  4. Try the failure or boundary case.
  5. Read the short robot glimpse and name the one familiar idea. The full excerpt is optional; do not assess syntax that has not been taught.

The Java toolbox gives small runnable introductions to inheritance, suppliers/lambdas, state and Optional when students first need them. The 52-check workbook is optional additional practice; it does not start a second required course.

Try the instructions with a real beginner

Code checks and an expert review cannot tell us where a first-time learner will hesitate. Before calling this classroom-tested, ask one student who has never programmed to follow Lessons 1–2 from the actual ZIP, then sample one later lesson per session. Let the written instructions do the guiding before offering a hint.

  • Can the student find the right folder, distinguish editor from Terminal, save, run, locate output and repair the deliberate semicolon error?
  • Can they predict a changed value and an exact boundary, trace a method call, explain the last loop comparison and reset one of two objects?
  • Can they find the required task without opening an advanced excerpt or an outside website?
  • Write down the exact step where help was needed and what hint helped. Revise that instruction; do not treat speed as the measure of understanding.

Use the curated outside readings only when another explanation would help. No outside subscription, quiz or account is required. Use the backup procedure until the student has learned Git.

Launchers and course scope

Students start Java through run.cmd (home-java-starter) and robot.cmd (sim-starter). Both use %PUBLIC%\wpilib\2026\jdk, which is where the WPILib 2026 installer puts Java for both “this user” and “all users” installs. On a computer with a non-standard install, set WPILIB_2026_JDK to the 2026 jdk folder. Stopping .\robot with Ctrl+C shows Windows’ “Terminate batch job (Y/N)?” prompt; students answer Y.

Windows 11 is the supported teaching route. Command-line Java, the launchers and native simulation checks are automated; a fresh student-account installer/VS Code walkthrough and native PathPlanner GUI open/save/preview remain separate manual checks. Other OS workflows are not yet classroom-tested. The sim-starter download stays on Commands v2 and stable 2026; never run the 2027 project importer on it. Reference tests use their own deploy copy under build; final student checks inspect the student’s selected implementation. Keep v11 local and use AdvantageScope for the independent home route.

From the model to the robot

Use the supervised transfer checklist after the capstone. Reviewed robot versions remain dated source evidence. The older TemplateSubsystem activities under Exercise Ladder are a collapsed mentor reference and require a separate implemented training baseline before use.

Teach SystemCore concepts now. Discuss Commands v3 after students understand commands. Move the classroom only when a released WPILib, vendor-library and editor combination has been tested together. Preserve the SYSTEMCORE-2027: migration comments.
