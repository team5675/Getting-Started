Mentor-supervised hardware

From simulation to the practice bot

Carry the habits across: predict, test, record and explain.

Use the real robot with a mentor

Finish the simulation capstone first. This is a supervised transfer checklist. The downloaded simulator has no deployment target or real hardware model; its fictional dimensions are not robot calibration.

1. Identify the approved project

Record the exact robot, repository commit, WPILib version, controller image and vendor versions with your mentor. The stable student project and pinned SystemCore bench are separate. Do not import the 2026 project with the 2027 importer or change one component of a pinned toolchain by itself.

2. Check devices before motion

Follow the team’s current hardware procedure for power, CAN and vendor tools. With the robot disabled, verify actual PDH voltage, gyro freshness and camera heartbeat. Construction of a software object does not establish device liveness. Learn where the main breaker and disable control are before enabling.

3. First movement, deliberately small

A mentor establishes a clear test area and the appropriate supported-robot procedure. Confirm module IDs, steering offsets, direction and control limits with the applicable vendor tools before a floor test. Make one low-speed change at a time. A simulation pass does not authorize unsupervised movement.

4. Measure and compare

Mark a short distance approved by the mentor, measure it with a tape, and compare actual movement with estimated pose and the log. Explain units and coordinate frames. Test the required alliance/heading cases with the real approved project; never solve a disagreement by adding a second heading flip.

5. Readiness and handoff

Review the log with a mentor, show the relevant Elastic/engineering display, record what was tested and what remains unknown, then use the team’s pre-match checklist. Git changes should be small enough that another student can explain them.

Your evidence packet

Project commit, pinned versions, test conditions, expected result, actual observation, log filename and one remaining question. Keep raw team logs local unless sharing is explicitly approved.
