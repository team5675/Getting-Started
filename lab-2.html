Simulation Lab 2 of 7

Drive with a default command

You will prove: movement and slow mode.

Before you start

Keep working in the same sim-starter folder, with your edits from Lab 1. Lost your work, or starting on a different computer? Stop the simulator and copy checkpoint 02 first; how checkpoints work shows which two files go where.

Do this lab in one sitting if you can. Save a backup before you change anything.

Make the edit

Your edit: After the controller lesson, add this line in configure, below your light binding. A default command runs whenever its subsystem is free. Open RobotContainer.manualDriveCommand and follow its runEnd action into TrainingDrive.driveFieldRelative.

// A default command runs when this subsystem has no other command.
// The supplied helper reads current input on each scheduler pass.
robot.drive.setDefaultCommand(robot.manualDriveCommand());

Run and observe

Use Teleop. Hold D for about one second: the robot moves right and X increases by about one meter. W moves up (+Y), A left (−X), and S down (−Y), matching your screen. Reset only while Disabled. Repeat with D and Shift held: the same time produces about 0.35 meters. Try A as well. Release all controls and check that requested speed becomes zero.

Try the boundary

Hold W and D together. The total translation speed stays at 1 m/s, not 1.41, because the XY vector is normalized together. Change Constants.SLOW_MODE_SCALE from 0.35 to 0.20, rerun and explain the result; restore 0.35 before the final student checks. A path later interrupts this default command by requiring the drive subsystem.

Connection to the 2027 practice code

The real bot uses a named SLOW_MODE_SCALE constant and a drivetrain default command. Scaling both signs of an input matters: reverse must slow down too. Reviewed source map.

Your turn · Tune one named setting

Change Constants.SLOW_MODE_SCALE, predict the distance over one second, and test both left and right. Restore the reference value before final checks.

Write the behavior you intend before typing. Save your experiment separately from the reference checkpoint.

Save your evidence

Write your prediction, observation and explanation. Save a backup or Git checkpoint when ready. Compare with answers/02 only after trying.
