Add a fresh command at a path marker

You will prove: a fresh action at a marker.

Before you start

Keep working in the same sim-starter folder, with your edits from Lab 4. Lost your work, or starting on a different computer? Stop the simulator and copy checkpoint 05 first; how checkpoints work shows which two files go where.

Do this lab in one sitting if you can. Save a backup before you change anything.

Make the edit

Your edit: Add this registration in configure. It runs during startup before any path is loaded. Commands.defer supplies a new action for each use. The declared requirement is light, so the marker does not compete with the path for the drive subsystem.

// Register BEFORE loading an auto/path. Defer constructs a fresh action
// on each use, and declares exactly the returned command's requirements.
NamedCommands.registerCommand("Checkpoint", Commands.defer(
        () -> robot.lightCommand().withTimeout(0.4)
                .beforeStarting(robot::eventReached), Set.of(robot.light)));

Run and observe

In PathPlanner, add an event marker to TrainingLine at waypoint-relative position 0.5, named Checkpoint. Give it a Named Command action also named Checkpoint, and save. Then stop the simulation (Ctrl+C) and start it again with .\robot: the program loads the path and the auto once, at startup, so a simulation that was already running still uses the old files. The same restart picks up your saved Java edit. For the first two-waypoint segment, 0.5 is halfway through the segment parameter, not a promise about elapsed time. If the editor controls are unfamiliar, compare the complete answers/05/TrainingLine.path file after trying.

Try the boundary

Run Autonomous twice, with Disabled between runs. The station’s event count increases once per run; the light flashes for 0.4 seconds while the robot continues driving. Interrupt during the event and confirm the light turns off. Misspelling the name or registering after loading the path can leave an event missing; check the Terminal.

Connection to the 2027 practice code

The practice robot registers LogMarker using Commands.defer(() -> Commands.print("[Auto] LogMarker reached"), Set.of()). Your event adds a subsystem requirement and cleanup to that same factory idea. Reviewed source map.
