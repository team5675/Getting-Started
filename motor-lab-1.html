Motor lab 1 · measure and explain

Measure your roller

Give a simulated Kraken X60 steady volts, read its speed from the log, and work out your roller’s kS and kV.

What you already did

This lab uses Motors 1 (kS, kV and steady speed), Lab 7 (a subsystem and a command that always ends) and your log workflow from Lab 3. Keep the same stable-2026 sim-starter project. The roller is a generic teaching mechanism with invented numbers, not a 2027 game mechanism. Allow 60–90 minutes.

You will prove: your measured kS and kV from a log, and code that never asks for more than 12 V and always ends at 0 V.

1. Add the motor lab files

Make a backup or Git checkpoint first. Stop the simulation, then type this in the Terminal:

.\robot motors1

It copies these files into the matching folders under src, and never replaces a file you already have:

  • main/java/frc/robot/subsystems/MotorRoller.java: your roller. Its TODOs are yours.
  • main/java/frc/robot/commands/RampVolts.java: a command you finish in step 7.
  • main/java/frc/robot/sim/RollerPhysics.java: supplied, the pretend world. Do not edit it.
  • main/java/frc/robot/sim/SimLimitSwitch.java: supplied, a pretend switch for the “Your turn”.
  • test/java/frc/robot/MotorLab1Test.java: the checks for this lab.

If Gradle answers Task 'motors1' not found, or the Terminal says the folder has no motor-lab-1 starter files, your folder came from an earlier download: add the motor lab folders. The starter compiles, but its unfinished parts should fail the checks.

2. Read what is supplied

Open MotorRoller.java (Ctrl+P, then type its name). Find these parts before you change anything:

  • Two volts fields. requestedVolts is what your code asked for. appliedVolts is what the motor really got. Like Lab 7’s request and sensor, they are different facts.
  • periodic() runs every loop. It copies the request to appliedVolts, except while the robot is disabled, when it applies 0 V just as a real motor controller does. Then it logs Training/Motor/AppliedVolts, SpeedRps, CurrentAmps and more.
  • simulationPeriodic() runs every loop, in simulation only. It moves the pretend world forward one loop: RollerPhysics, a Kraken X60 model from WPILib plus friction.

This MotorRoller is simulation only. It has no motor controller in it: it keeps your volts request, and it reads speed and current from the pretend world. On a real robot, physics happens by itself, but the subsystem also needs a motor controller object. Your code sends the volts request to that object and reads the real speed and current back from it. Your commands can keep the same shape; the motor and sensor connections inside the subsystem change. Motor lab 3 makes that connection for a simulated TalonFX. BOB’s SPARK MAX uses REV’s library instead, so a mentor shows that version.

3. TODO 1 · never ask for more than the battery has

In setVolts, store the request kept between −12 V and +12 V. MAX_VOLTS is already 12.0. Use the clamp from Motors 1:

requestedVolts = MathUtil.clamp(volts, -MAX_VOLTS, MAX_VOLTS);

4. TODO 2 · a command that holds volts

Replace the placeholder return in runAtVolts with:

return runEnd(() -> setVolts(volts), () -> setVolts(0.0)).withName("Run at " + volts + " V");

runEnd is a method every subsystem has. It builds a whole command in one line, and that command requires this subsystem, just like addRequirements(roller) in Lab 7:

PartWhen it runs
() -> setVolts(volts)every loop while the command is scheduled
() -> setVolts(0.0)once, when the command ends: released, interrupted or disabled
.withName(...)gives the command a readable name for logs and errors

The second lambda is the cleanup that Lab 7 taught: every ending sets 0 V.

5. Run the step test

The supplied stepTest() uses your runAtVolts: 3 V, then 6 V, then 9 V, two seconds each, then 0 V. Add these lines inside StudentProgram.configure, after your other connections:

frc.robot.subsystems.MotorRoller motor = new frc.robot.subsystems.MotorRoller(
        () -> robot.input().objectPresent());
robot.driver.b().onTrue(motor.stepTest());

Put // in front of Lab 7’s robot.driver.b()... line so B starts only one thing. Keep Lab 7’s files; its check still runs.

  1. Save, start the simulation with .\robot and open the station. Choose Teleop. Leave Object present clear.
  2. Click the keyboard area and press B once. The station’s button still says “Capture · B (Lab 7)”: it is the same B button. The test takes six seconds.
  3. Click Disabled, stop Java with Ctrl+C and open the newest log, as in Lab 3. Graph Training/Motor/AppliedVolts and Training/Motor/SpeedRps; they may be under RealOutputs.
  4. For each step, read the speed just before the step ends, where the line is flat. Copy this table into learning-notes.txt and fill it in.

Two things to notice. AppliedVolts drops to 0 for one 20 ms loop between steps: each step’s end runs before the next step starts. And Training/Motor/CurrentAmps jumps at the start of every step, then falls, as the spin-up picture in Motors 1 showed.

6. TODO 4 · work out kV and kS

Use your 3 V and 9 V readings, exactly as with the practice wheel:

  • kV = (9 − 3) ÷ (speed at 9 V − speed at 3 V)
  • kS = 3 − kV × (speed at 3 V)

Now test your numbers on the reading you did not use: predict the 6 V speed with (6 − kS) ÷ kV. It should match your measured 6 V speed to about 0.1 rps. If it does not, re-read the log.

Type your two numbers into the constants at the top of MotorRoller.java, with three decimal places:

public static final double KS_VOLTS = 0.000;           // your kS
public static final double KV_VOLTS_PER_RPS = 0.000;   // your kV

Replace each 0.000 with your own measurement. Leave KP_VOLTS_PER_RPS at 0.0 until Motor lab 2.

PAUSE & PREDICT

Where does it start to turn?

Before step 7: if you raise the volts slowly from 0, at what volts will the roller start to turn? Use your kS.

7. TODO 3 · ramp the volts slowly

In RampVolts.execute, ask for volts that grow with time. The supplied timer restarts when the command starts:

roller.setVolts(voltsPerSecond * timer.get());

In StudentProgram, replace the step test line with a ramp of 0.5 V per second:

robot.driver.b().whileTrue(new frc.robot.commands.RampVolts(motor, 0.5));

whileTrue runs the command only while B is held, then ends it. Run the simulation in Teleop, hold B for about four seconds, then release. In the log, find the first moment SpeedRps rises above 0 and read AppliedVolts at that moment. That is kS, seen a second way. It reads a little high, because the speed reading is one loop old and the roller needs a moment to pick up speed. Is it within about 0.05 V of your KS_VOLTS?

8. Check your implementation

Disable and stop the simulation, then run only this lab’s checks:

.\robot test --tests "frc.robot.MotorLab1Test" --rerun-tasks

The checks cover the 12 V limit, the command’s requirement, steady speed at 6 V, 0 V when a command ends or the robot is disabled, no restart after re-enabling, the ramp, and your two measurements (kS within 0.05 V and kV within 5 percent of the model). A failed check prints its reason: read it before changing code. Compare with motor-lab-1/answer only after trying. Passing shows your code and numbers match this model; a real roller’s kS and kV must be measured on that roller.

Your turn · a switch starts the roller

A favorite bench demonstration: press a limit switch, and a motor starts. Add this inside configure, after the motor lines:

new frc.robot.sim.SimLimitSwitch(0, () -> robot.input().objectPresent()); // simulation only
edu.wpi.first.wpilibj.DigitalInput limitSwitch = new edu.wpi.first.wpilibj.DigitalInput(0);
new edu.wpi.first.wpilibj2.command.button.Trigger(() -> !limitSwitch.get())
        .whileTrue(motor.runAtVolts(4.0));

The station’s Object present box is now your switch: press O in the keyboard area, or click the box, to press or release it. DigitalInput(0) reads DIO port 0. A Trigger can watch any true-or-false question, not only a button. The ! (“not”, from Lesson 7B) is there because a pressed switch reads false:

  1. Predict: the box also adds the roller’s load, because MotorRoller was made with the same box. Will the speed at 4 V be more or less than (4 − kS) ÷ kV? Check the log.
  2. Take the ! away and run again. What happens, and why?
  3. Press B while the switch is held. Two commands want the one roller; which one wins? Explain it with Lab 7’s rule.

On real hardware. The team’s Bot in a Box bench kit has a roboRIO with DIO ports. With a mentor, a limit switch can be wired to DIO 0 and read with the same DigitalInput and Trigger lines. The SimLimitSwitch line is only for simulation and does nothing on a robot.

Connection to team code

Team subsystems keep the same split: a request, the measured result, and logs of both. Their motors are characterized with WPILib’s SysId, which automates a ramp test and a step test like yours and fits kS and kV from the log. Motor lab 2 uses your kS and kV to hold a speed.
